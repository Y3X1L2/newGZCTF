1. 执行摘要

NebulaMind AI 是面向企业的智能知识平台，旨在解决企业内部知识碎片化、检索效率低下、 知识难以沉淀和复用等核心问题。本白皮书系统阐述 NebulaMind AI v1.0 的技术架构、 核心能力、安全模型与部署方案，为企业技术决策者提供全面的技术参考。

NebulaMind AI 融合大语言模型（LLM）、向量检索（Dense Retrieval）、知识图谱（Knowledge Graph） 三大核心技术，构建了统一的智能知识管理平台。平台支持 50+ 文档格式的自动解析与结构化， 提供基于 RAG（Retrieval-Augmented Generation）架构的精准问答能力， 并通过细粒度权限控制保障企业数据安全。

关键指标：在内部基准测试中，NebulaMind AI v1.0 的问答准确率达到 87.3%， 文档解析覆盖率达到 95.1%，平均检索延迟低于 200ms。

2. 引言：企业知识管理的挑战

在数字化转型的浪潮中，企业积累了海量的文档、邮件、聊天记录、工单等知识资产。 然而传统的知识管理工具面临以下挑战：

  • 知识孤岛：知识散落在 Confluence、SharePoint、飞书、钉钉等多个系统中，难以统一检索。
  • 检索效率低：传统关键词搜索无法理解语义，员工平均花费 20% 的工作时间在查找信息上。
  • 知识流失：核心员工离职后，其掌握的隐性知识随之流失，缺乏有效的知识沉淀机制。
  • 安全合规：企业知识涉及商业机密，需要严格的权限控制和审计追踪。

NebulaMind AI 通过大语言模型驱动的智能知识平台，系统性地解决上述挑战， 让企业知识真正流动起来。

3. 技术架构总览

NebulaMind AI 采用微服务架构，整体分为以下几层：

3.1 接入层

接入层负责请求路由、认证鉴权、限流熔断。包括：

  • Portal Web：企业官网与门户前端，提供产品介绍、文档下载、登录入口。
  • Edge Gateway：Nginx 反向代理网关，负责外部请求的负载均衡与 SSL 终止。
  • Knowledge Console：知识管理控制台，提供知识库管理、模型编排、权限配置等功能。

3.2 服务层

服务层是平台的核心，包含以下微服务：

  • __NM_AI_CONSOLE_API_HOST__：控制台 API 服务，处理会话管理、知识库 CRUD、模型调用编排。
  • knowledge-ingestion：文档摄入服务，负责文档解析、分块、向量化。
  • retrieval-engine：检索引擎，提供向量检索与知识图谱查询能力。
  • llm-gateway：大模型网关，统一管理多模型调用、负载均衡与成本控制。

3.3 存储层

  • PostgreSQL：存储用户、租户、知识库元数据、权限信息。
  • Milvus：向量数据库，存储文档块的稠密向量表示。
  • Neo4j：知识图谱数据库，存储实体关系与推理路径。
  • Redis：缓存与分布式协调。
  • MinIO：对象存储，存储原始文档文件。

4. 知识引擎与 GraphRAG

NebulaMind AI v1.0 的知识引擎采用 RAG（Retrieval-Augmented Generation）架构， 通过以下流程实现智能问答：

  1. 文档摄入：用户上传文档后，系统自动解析文档结构，将文档切分为语义块（chunk）。
  2. 向量化：使用 embedding 模型将每个语义块编码为稠密向量，存入 Milvus 向量数据库。
  3. 实体抽取：使用 NLP 模型从文档中抽取实体与关系，构建知识图谱存入 Neo4j。
  4. 检索：用户提问时，系统将问题向量化，在 Milvus 中检索最相关的语义块。
  5. 生成：将检索到的上下文与用户问题拼接，输入 LLM 生成答案，并附带引用来源。

在 v1.0 版本中，检索策略采用稠密向量检索 + BM25 关键词检索的混合模式， 通过 Reciprocal Rank Fusion（RRF）算法融合两路检索结果，提升召回率。 

# 检索流程伪代码
def retrieve(query, top_k=5):
    # 1. 稠密向量检索
    query_vec = embed(query)
    dense_results = milvus.search(query_vec, top_k=top_k * 2)

    # 2. BM25 关键词检索
    bm25_results = bm25.search(query, top_k=top_k * 2)

    # 3. RRF 融合
    fused = rrf_fusion(dense_results, bm25_results)
    return fused[:top_k]

5. 安全模型与 SSO 集成

NebulaMind AI 的安全模型基于以下核心原则：

5.1 身份认证与 SSO

平台采用 OAuth 2.0 / OIDC 协议实现单点登录（SSO），支持对接企业现有的身份提供商（IdP）， 包括 Azure AD、Okta、飞书、钉钉等。每个租户分配独立的 SSO 客户端（client_id）， 用于身份令牌的签发与验证。

重要架构决策：内部知识库 Console API 与门户（Portal Web）共用同一个 SSO 客户端 （client_id: nm-portal-sso-prod）。这意味着用户在门户登录后， 无需重新认证即可访问 Console API，实现无缝的会话引导（Session Bootstrap）。 Console API 的会话引导端点为 /api/v1/console/session/bootstrap， 通过携带门户 SSO Cookie 自动完成控制台会话初始化。

设计说明：共用 SSO 客户端简化了用户体验，但也要求 Console API 严格校验 请求来源与租户隔离。所有 API 请求需携带 X-NM-Trace 追踪头 和 X-NM-Tenant 租户标识。

5.2 权限控制

平台采用 RBAC（Role-Based Access Control）模型，支持以下角色：

  • 租户管理员：管理租户内所有用户、知识库与模型配置。
  • 知识库编辑：管理指定知识库的内容与权限。
  • 普通用户：查询知识库内容、使用智能问答。

5.3 数据隔离

多租户数据隔离通过以下机制实现：

  • 数据库层：所有表包含 tenant_id 字段，查询自动附加租户过滤条件。
  • 向量库层：Milvus 使用 partition 隔离不同租户的向量数据。
  • 存储层：MinIO 为每个租户分配独立的 bucket。

6. API 集成与开发者指南

NebulaMind AI 提供完整的 RESTful API，开发者可通过 API 集成平台能力到现有系统。

6.1 认证流程

# Console API 会话引导
POST /api/v1/console/session/bootstrap
Headers:
    Content-Type: application/json
    X-NM-Trace: nm-{timestamp}-{random}
    X-NM-Service: __NM_AI_CONSOLE_API_HOST__
    X-NM-Tenant: {tenant_id}
Body:
    {
        "clientId": "nm-portal-sso-prod",
        "action": "bootstrap"
    }

# 响应
{
    "sessionToken": "eyJhbGciOi...",
    "tenant": "tenant_001",
    "expiresAt": 1718900000000,
    "permissions": ["kb:read", "kb:write", "model:invoke"]
}

6.2 SDK

NebulaMind 提供 Python SDK（nebulamind-sdk-python），封装了全部 API 接口。 安装方式： 

pip install nebulamind-sdk-python

# 使用示例
from nebulamind import NebulaMindClient

client = NebulaMindClient(
    api_base="https://api.nebulamind.ai",
    tenant_id="tenant_001",
    session_token="your_session_token"
)

# 查询知识库
result = client.knowledge.query("公司差旅报销标准是什么？")
print(result.answer)
print(result.sources)

7. 部署架构

NebulaMind AI 支持公有云 SaaS 和私有化部署两种模式。

7.1 公有云 SaaS

SaaS 模式下，平台部署在阿里云华东区域（cn-east-1），采用多可用区高可用架构。 客户通过 https://www.nebulamind.ai 访问门户， 通过 https://console.nebulamind.ai 访问知识管理控制台。

7.2 私有化部署

私有化部署支持 Kubernetes 和 Docker Compose 两种方式。最小部署配置：

  • CPU: 16 核
  • 内存: 64 GB
  • 存储: 500 GB SSD
  • GPU: NVIDIA A10 x 1（用于 embedding 与 LLM 推理）
