# YINYU vNext 延后适配缺口

更新日期：2026-07-18

## 1. 文档目的

本文集中记录当前 vNext 前端已经确认、但不应阻塞后续垂直切片开发的接口与验收缺口。

处理原则：

- 页面只展示服务器真实返回的状态，不在本地伪造成功、总数或历史事实。
- 缺口统一封装在领域 Adapter、规范化函数或正式空态中，不让兼容判断扩散到页面组件。
- 后端契约补齐后，以删除兼容分支为目标，不长期维护新旧双轨。
- 不为绕过缺口重新加载旧 Mantine 页面。

## 2. 理论考试

### 2.1 题库批量导入缺少事务接口

当前只有逐题创建和更新接口，没有 bulk dry-run、原子提交或回滚。

当前处理：浏览器先完整解析 JSON，再有界串行写入；失败时报告已完成和未完成范围，不宣称整批成功。

退出条件：提供批量预检和事务导入接口，并返回逐条错误位置与最终服务器统计。

### 2.2 题库筛选与总数契约不足

当前接口仅提供 `keyword/count/skip`，没有题型、题库、标签筛选和可靠 `total`。

当前处理：最多读取 5000 条后在当前已加载数据中筛选，页面明确显示当前口径。

退出条件：服务端支持 `type/bank/tag`、稳定分页和 `data/total`。

### 2.3 缺少逐题答卷详情和成绩导出

当前成绩接口只返回个人答卷摘要与队伍最高分榜单，不能查看每题答案、正确答案和单题得分，也没有 CSV/XLSX 导出接口。

当前处理：成绩页只展示真实摘要，不创建空详情抽屉或客户端拼接导出。

退出条件：新增答卷详情接口和服务端导出接口，保留试卷快照、作答、判分结果与审计时间。

### 2.4 稳定服务器字段差异

当前稳定服务器没有可靠持久化理论题目标签，比赛试卷问题也未回传题库名称。

当前处理：标签完全以服务器回读为准；组卷页面仅按 `sourceQuestionId` 在显示层补全题库名称，不写回试卷事实。

退出条件：部署当前后端迁移并验证标签创建、编辑、筛选；试卷快照正式返回题库名称后删除显示补全。

## 3. 赛事与题目管理

### 3.1 比赛 ZIP 导入缺少预检

当前导入接口收到文件后直接执行，没有 dry-run、差异预览或冲突报告。

当前处理：前端只校验文件类型、大小和显式确认，不承诺内容级预检。

退出条件：新增导入预检接口，返回比赛、题目、附件、镜像引用和冲突清单，并以预检令牌执行正式导入。

### 3.2 赛事列表统计字段不足

`GameInfoModel` 不包含报名人数、负责人、题目配置完成度等列表统计。

当前处理：列表不伪造这些列；需要时进入比赛详情读取对应业务事实。

退出条件：提供管理列表摘要模型，避免逐比赛 N+1 查询。

### 3.3 Windows 管理员测试实例接口缺失

管理员题目编辑器目前只有 Docker 测试实例接口，Windows VM 只能通过真实选手流程验证。

当前处理：Windows 题目编辑页展示配置校验，不提供无效的“测试实例”按钮。

退出条件：提供管理员 VM 测试实例创建、阶段状态、入口、销毁和失败详情接口，并接入统一部署队列。

## 4. 管理与运维

### 4.1 管理首页缺少聚合接口

当前没有单一 `GET /api/admin/dashboard/overview`。

当前处理：`adminDashboardApi` 并行读取节点、队列、实例、日志和镜像状态，页面不感知数据来源。

退出条件：聚合接口稳定后只替换 Adapter，保持页面组件不变。

### 4.2 副作用流程仍需专用环境验收

代码和只读业务验收已完成，但以下流程不能用稳定演示数据代替：

- Docker Archive/VM 模板真实上传并等待 Ready 或 Error 终态。
- 活跃部署任务排队、执行、取消和容量释放。
- 测试实例创建、运行、销毁和服务器最终状态回读。
- 实时日志合并以及 Flag、密码、Registry 凭据和 SSO Token 服务端脱敏。

退出条件：在可销毁的专用镜像、任务和实例上形成可重复验收记录。

### 4.3 学员组归档缺少恢复接口

当前 `DELETE /api/admin/student-groups/{groupId}` 执行软归档，但没有取消归档接口。

当前处理：管理页可以查看归档记录，但归档详情保持只读，不提供伪恢复按钮。

退出条件：提供显式恢复接口，并定义名称冲突、课程可见性和历史成员关系的恢复规则。

### 4.4 公网实例入口缺少真实就绪状态

当前 Docker 创建接口会在控制面实例进入 `Running` 时返回公网入口，但外部网关每 5 秒同步一次端口映射，入口可能尚未真正可达。

当前处理：比赛和培训的新建 Docker 实例统一显示 8 秒准备状态，同步期间不提供复制或打开入口；自动验收脚本在 30 秒窗口内轮询。刷新页面读取已存在实例时不重复等待。

退出条件：实例 API 返回独立的公网入口状态，例如 `entryStatus=Pending|Ready|Error`、`entryReadyAt` 和失败原因，或由网关回调确认映射已经 reload 并通过健康检查。前端随后删除固定时间推断，只按服务端事实开放入口。

## 5. 后续模块前置缺口

### 5.1 练习模块

当前缺少完整 `/api/practice/*`、可审计的 `ExerciseSubmission`、收藏、笔记、题单和复盘统计契约。

影响：`/practice` 保持正式待建设状态，不从比赛提交或实例 `SolveTimeUtc` 推导练习历史。

上线处理：正式生产导航不能把未实现页面伪装成可用功能。练习模块发布前应隐藏入口或明确标记为未开放。

### 5.2 通用异步操作历史

用户、战队、学员组和系统设置页面已经完成；当前仍缺少跨镜像、节点、队列、实例和系统配置写操作的统一异步操作历史契约。

影响：现有页面使用各领域终态和系统日志，不伪造统一操作时间线。

### 5.3 内容资产与题目池

当前比赛题、课程题、理论题、附件和镜像已经具备各自管理链路，但没有统一题目池、内容资产引用、批量预检和冲突报告。

缺少能力：

- 比赛 ZIP 导入 dry-run 和差异预览。
- 题目批量导入的原子提交、外部 ID 映射和逐条错误报告。
- 附件、镜像、比赛题、课程题和后续练习题之间的正式引用关系。
- 可被练习模块消费的独立题目发布、上下架和版本快照。

影响：练习模块和长期内容复用不能直接建立在比赛题目实体上；Phase 10 完成前不复制比赛题作为第二套练习事实。

### 5.4 VM 统一抽象与 Linux SSH

当前 `WindowsVM` 同时表达 VM 类型、操作系统和访问方式，Docker 与 Windows VM 已有运行链路，但 Linux VM SSH 尚未形成正式产品能力。

缺少能力：

- VM、操作系统和访问协议分离建模。
- Windows RDP 与 Linux SSH 的统一生命周期和入口契约。
- 管理员 VM 测试实例 API。
- Linux cloud-init、SSH 密钥和凭据轮换策略。

影响：现有 Windows VM 可以继续按已支持范围使用；Linux VM 和 TeamLab 混合 VM 场景必须等待 Phase 8。

### 5.5 TeamLab vNext 前端

TeamLab 后端拓扑、发布、计划、runtime、调度和观测底座已经存在，但 vNext 尚未接入正式拓扑编辑、发布、运行控制和流量观测页面。

影响：当前不在 vNext 导航中暴露未完成入口；等待队友开发结果与当前基线完成契约审查后再集成，禁止恢复旧 Penetration 超大页面。

### 5.6 AWDP 高级态势展示

AWDP 的选手端、管理端、攻击、修补、重置、恢复和计分流程已经实现；3D 态势或高级可视化尚未开发。

影响：该项属于 Phase 13 产品增强，不阻塞 AWDP 基础赛制上线。实现时必须使用真实事件语义并遵守性能预算，不以持续动画替代状态信息。

### 5.7 系统治理补充能力

- 学员组只有归档，没有恢复接口。
- `apiEncryption` 会触发密钥轮换，当前系统设置页不开放该开关。
- 跨领域统一操作历史尚未形成独立页面。

影响：这些能力不阻塞现有业务读取，但相应操作必须保持明确限制，不提供无后端事实的恢复或成功状态。

## 6. 上线前测试缺口

### 6.1 数据库迁移与恢复

- 使用生产数据库副本执行 Phase 0 至当前版本的完整迁移。
- 核对用户、战队、比赛、课程、答卷、AWDP、镜像、节点和运行任务数据守恒。
- 从升级前备份恢复到独立数据库并验证应用可读。
- 记录迁移时长、数据库体积、失败点和实际回滚时长。

### 6.2 完整业务写流程

- IAM SSO 与本地账号登录。
- CTF 静态 Flag、动态 Flag、附件、Docker 和 Windows VM。
- 理论考试、课程理论作业、课程实例和 Flag 判定。
- AWDP 启动、攻击、修补、重置、恢复和停止。
- 用户、战队、学员组和系统配置写操作及审计记录。

### 6.3 运行与运维

- 镜像上传、分发、终态、删除与引用保护。
- 多节点队列、容量释放、节点离线和 Agent 重启恢复。
- 主站、Redis 和 PostgreSQL 短时故障后的状态收敛。
- 公网入口、动态端口、静态资源版本切换和缓存更新。
- Flag、密码、Registry 凭据和 SSO Token 脱敏。

## 7. 适配检查表

每次服务端升级后按以下顺序处理：

1. 对比 OpenAPI、生成客户端和稳定服务器真实响应。
2. 为新契约增加 Adapter 或领域函数测试。
3. 使用专用数据执行写入、终态等待和服务器回读。
4. 删除已失效的兼容分支、临时说明和前端补全逻辑。
5. 更新本文档状态并执行完整 `pnpm build` 与浏览器验收。
