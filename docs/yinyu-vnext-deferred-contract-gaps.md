# YINYU vNext 已知契约与验收缺口

更新日期：2026-08-16

本文只记录当前源码尚未闭环、但不应靠前端伪造或恢复旧页面解决的事项。阶段计划、已经关闭的问题和一次性测试数字不在此维护。

## 1. 处理原则

- PostgreSQL 和领域状态是业务事实源；页面不得从日志、固定等待时间或客户端计数推断成功。
- 兼容处理集中在 feature API adapter，后端统一后删除兼容分支。
- 接口缺失时显示真实限制或不提供入口，不构造无效按钮。
- 本文的缺口是否关闭必须由当前源码、自动化测试和真实运行验收共同证明。

## 2. 内容、题库与导入

### 2.1 理论题批量导入

浏览器端可以解析并逐题写入，但服务端仍缺少统一的批量预检、原子提交和逐条回滚结果。网络中断可能形成部分成功。

退出条件：后端提供 dry-run、事务提交、冲突策略和逐条错误位置；前端改为展示服务器预检结果。

### 2.2 比赛 ZIP 导入

现有导入缺少完整差异预览和冲突报告，前端只能校验文件类型、大小并要求显式确认。

退出条件：服务端返回比赛、题目、附件、镜像引用和冲突清单，并使用预检令牌执行正式导入。

### 2.3 统一内容资产

比赛题、课程题、练习题、理论题、附件和镜像已有各自链路，但仍不是统一版本化资产模型。跨域导入依赖显式 snapshot 或 binding，不能共享可变业务实体。

退出条件：建立题目发布版本、附件/镜像引用、导入来源和冲突策略，并为比赛、培训和练习提供稳定快照语义。

## 3. 查询与管理体验

### 3.1 管理首页聚合

当前管理首页由 adapter 并行读取节点、队列、实例、日志和镜像状态，没有单一聚合接口。该实现可用，但请求数量会随模块增加。

退出条件：后端提供稳定的管理概览 DTO；只替换 adapter，不改页面组件。

### 3.2 服务端筛选和总数

部分题库、日志和管理列表的筛选维度或可靠 `total` 不完整，前端只能对已加载范围做二次筛选。

退出条件：相关列表提供服务端筛选、稳定排序、游标或页码以及准确总数；页面明确移除“当前已加载范围”口径。

### 3.3 统一异步操作历史

镜像、节点、队列、实例和系统配置分别有领域状态或日志，但没有统一、可查询的异步操作历史页面。

退出条件：建立稳定 operation 查询契约、关联 ID、终态和保留策略，页面只消费该事实。

### 3.4 学员组恢复

学员组支持软归档但缺少显式恢复接口。归档记录应保持只读，不能提供伪恢复操作。

退出条件：定义名称冲突、历史成员关系和课程可见性的恢复规则并提供恢复 API。

## 4. 运行与基础设施

### 4.1 Windows VM 实机门禁

比赛 Windows VM 已按镜像固定 RDP 配置、KVM 能力和统一运行队列实现；仍需对每个候选镜像执行真实验证。培训 Windows VM 不在当前产品范围。

验收必须包含：双实例启动、Guacamole 登录、内网 mstsc 登录、文本剪贴板、实例隔离、销毁清理、节点重启恢复和日志脱敏。管理员题目编辑器仍缺少独立的 VM 测试实例接口时，应通过专用测试比赛验证。

### 4.2 Linux VM 与统一访问抽象

Docker 和 Windows VM 已有运行链路，Linux VM SSH 尚未形成正式产品能力，VM 类型、操作系统和访问协议也未完全独立建模。

退出条件：定义通用 VM 生命周期、OS profile、访问端点和凭据语义，并提供 Linux 镜像初始化与 SSH 验收链路。

### 4.3 镜像和调度真实验收

以下流程不能只凭 mock、单元测试或页面显示判定完成：

- Docker Archive 与 VM 模板上传、校验、分发和终态；
- 多节点容量预留、节点离线、任务取消和容量释放；
- 公网入口 `Pending -> Ready`、网关 ACK、失败恢复和实际访问；
- 主站、Redis、PostgreSQL 或 Agent 短时故障后的状态收敛。

每次生产候选版本应在可销毁的专用数据上保存验收记录。

### 4.4 生成客户端漂移

实时 OpenAPI 与已提交生成客户端可能因生成器版本、排序或历史快照产生大范围机械差异。业务功能不得长期依赖手写重复类型。

退出条件：固定生成器和 OpenAPI 来源，分类审核 breaking/additive diff，迁移所有调用方后一次性提交生成结果，并在 CI 检查快照漂移。

## 5. TeamLab 与 AWDP

### 5.1 TeamLab 生产规模验收

TeamLab 已有拓扑、发布、计划、runtime、远程访问、流量和管理/选手路由。仍需持续验证多节点故障、双 Worker 竞争、长时间流量采集、PCAP、资源残留和容量上限。

退出条件：按 [TeamLab 基础验收手册](./commercialization/runbooks/teamlab-foundation-acceptance.md) 在真实节点完成规模、故障和清理验收，并记录可重复证据。

### 5.2 AWDP 手工验收

AWDP 的管理和选手流程已有实现，但本机自动执行攻击、补丁和恢复可能触发安全软件。代码门禁不能替代授权环境中的完整比赛流程。

退出条件：测试人员按 [AWDP 手工验收指南](./yinyu-awdp-manual-acceptance.md) 完成启动、攻击、修补、重置、恢复、计分和停止，并核对审计日志。

## 6. 认证、日志和安全事实

- IAM SSO 必须在可达门户上验证 token 包装结构、自动建号、稳定外部身份绑定和返回地址白名单。
- Flag、token、Cookie、Registry 凭据、WireGuard 私钥、VM 凭据和完整 user-data 不得进入日志、文档或测试快照。
- 日志覆盖需要真实验证请求、队列、调度、Agent、实例和入口的同一 correlation 链；日志文本不能反向成为恢复事实源。
- 系统设置中会触发密钥轮换或破坏兼容性的配置，在缺少完整后端工作流前不开放普通切换入口。

## 7. 上线前最低验收

1. 使用生产数据库副本执行当前 migration head 的前向升级，并从升级前备份恢复一次。
2. 核对用户、战队、比赛、课程、练习、答卷、AWDP、镜像、节点、队列和 TeamLab 数据守恒。
3. 验证本地登录与 IAM SSO。
4. 验证 CTF 静态/动态 Flag、附件、Docker 和 Windows VM。
5. 验证练习、理论考试、课程作业、课程实例和章节完成条件。
6. 由授权测试人员完成 AWDP 手工验收。
7. 验证用户、战队、学员组和系统设置写操作及审计记录。
8. 验证多节点调度、镜像分发、节点离线恢复和公网入口。

## 8. 缺口更新规则

服务端或前端完成相关能力后：

1. 对比实时 OpenAPI、生成客户端和真实响应；
2. 增加 adapter、领域状态机和必要集成测试；
3. 使用专用数据执行写入、终态等待与服务端回读；
4. 删除兼容分支和临时说明；
5. 更新本文、`current-state.md` 和相关运维手册。
