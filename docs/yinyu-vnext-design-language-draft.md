# YINYU vNext 前端设计语言规范

> 状态：现行基线（2026-08-16 校核）
>
> 方向关键词：现代、简约、几何动画、日间优先、复杂业务可读
>
> 页面、API 与交互开发规格：[YINYU vNext 页面交互与 API 设计规格](./yinyu-vnext-page-interaction-api-spec.md)

## 1. 范围与前提

本方案按一套新的前端产品设计，不以修补旧视觉层为目标。

保留：

- 后端 API、权限语义、业务规则和数据模型。
- 对外链接确有依赖的核心 URL。
- 比赛、培训、理论考试、AWDP、多节点、TeamLab 等既有业务能力。
- 后续新增“练习”模块所需的一级导航和页面扩展能力。

不继承：

- `前端设计方案` 目录下的全部废弃原型和视觉尝试。
- 旧版全局 CSS、页面级覆盖链、全局 Three.js/流体背景和大面积毛玻璃。
- 旧版暗色优先、霓虹绿色主导、蜂巢噪点和“泛终端化”表达。

新前端可以复用稳定 API 客户端、领域类型和经过验证的纯业务逻辑，但视觉组件、页面壳、导航、主题和动效从零建立。

## 2. 参考站点结论

### 2.1 HGame / Ret2Shell

值得借鉴：

- 日间与夜间使用同一套语义令牌，不是两个互不相关的皮肤。
- 全局导航、模块内导航和主内容区层次明确。
- 背景几何保持固定，页面内容独立切换，空间关系稳定。
- 页面切换以 200-300ms 的淡入和短距离位移为主。
- Logo 描边、路径绘制、状态点等动画和“终端”主题有关联。
- 状态色数量少，默认界面以中性色为主。

不应照搬：

- 六边形已经成为其高度可识别的品牌母题。
- 全站等宽字体会降低中文正文、表单和长时间操作的可读性。
- 日间主题的蓝灰对比偏低，部分表面层次不够清楚。
- 大量 `transition: all`、逐元素 700ms 换色和毛玻璃会增加渲染成本。
- 首次加载先播放长背景描边，内容出现较晚，容易形成空白等待。
- 背景图形在所有页面使用同一强度，和具体业务缺少关系。

### 2.2 AI Coding Dictionary

值得借鉴：

- 几何对象不仅是装饰，还表达概念之间的关系。
- 鼠标、碰撞、连线和颜色切换形成有生命力的场景。
- 信息弹层打开后，背景仍保留上下文。

使用边界：

- 物理粒子和持续画布适合首页、拓扑概览或特殊数据展示。
- 不适合题目列表、课程正文、考试和节点管理等高频操作页。
- 不能让全站业务页面长期承担持续 Canvas、噪点和模糊成本。

### 2.3 Vercel

值得借鉴：

- 只使用一个强几何符号建立品牌识别，不把符号铺满所有页面。
- 日间页面依靠比例、留白和黑白对比成立，不依赖深色氛围遮盖问题。
- Canvas/3D 只服务于品牌展示区域，普通内容保持轻量。

### 2.4 Linear

值得借鉴：

- 复杂工作台依靠稳定网格、弱边框和密度层级组织，而不是大量装饰卡片。
- 动效主要解释对象从哪里出现、去了哪里、状态如何变化。
- 工具栏、侧栏、详情区和数据区之间的职责清楚。

### 2.5 IBM Carbon Motion

采用其“生产性动效 / 表达性动效”分类：

- 生产性动效用于导航、展开、筛选、表格、抽屉、状态更新，短而直接。
- 表达性动效只用于首次进入、模块切换、主题切换、重要成功节点。
- 一个视图中只保留一个表达性动效焦点。

### 2.6 洛谷、HGame 与 NSSCTF 用户页

洛谷用户页值得借鉴：

- 封面、头像、用户名和简介先建立完整身份区，再紧接关注、提交、通过、排名等关键数字，阅读顺序自然。
- 做题热力图、等级分趋势和右侧账户信息在同一页面形成“当前结果 + 长期成长 + 身份事实”的闭环。
- 主内容和辅助信息采用稳定宽度的双栏布局，在大屏上仍保持明确的阅读中心。
- 用户页不仅是资料卡，也是进入练习记录、比赛经历和个人设置的长期入口。

不直接照搬：

- YINYU 当前没有关注、粉丝、获奖认证、全局等级分和自定义封面等稳定数据，不能用空数字伪造完整度。
- 洛谷的统计语义建立在个人 OI 提交上，而 YINYU 同时包含个人提交、队伍成绩、理论考试、培训和 AWDP，必须明确归属。
- 大面积用户自定义封面会引入上传、审核、裁切和可读性问题，首版不作为必要能力。

HGame 用户页值得借鉴：

- 左侧身份事实和右侧赛事时间线职责清楚，适合表达“用户是谁、参与过什么”。
- 时间线的单行事件、时间和目标链接可以用于 YINYU 的参赛、结课和里程碑记录。

不直接照搬：

- 当前页面数据维度偏少，无法承载做题成长、培训进度和多赛制经历。
- 邮箱等联系信息不应默认出现在公开用户页。

NSSCTF 用户页值得借鉴：

- 身份横幅、标签导航、汇总数字、解题热力图、趋势图和分类雷达形成较完整的 CTF 用户画像。
- 雷达图能快速表达 WEB、PWN、RE、CRYPTO、MISC 等方向差异，适合 YINYU 的多分类题目体系。
- “主页 / 统计”切换只替换内容区，身份区保持稳定，切换成本低。

需要修正：

- 仅按用户最强分类相对归一化会夸大低题量用户。例如只解出一道 WEB 题，也可能形成接近满轴的视觉结果。
- 雷达图不能代替真实数据。每个维度必须同时提供解题数、尝试题数、提交数和正确率。
- 大面积渐变横幅和多层圆角卡片不符合 YINYU 的“折域”语法。

YINYU 的组合结论是：采用洛谷的身份与信息层级、NSSCTF 的多维解题表达、HGame 的经历时间线，但使用自身的数据口径、隐私规则和几何语言重新设计。

## 3. 推荐方向：Folded Domain / 折域

“折域”来自两个产品特征：

1. 现有 YINYU 标志具有折翼、折面和 Y 形汇聚轮廓。
2. 平台处理比赛域、课程域、节点域、网络域和权限域，天然具有边界、路由和分区概念。

### 3.1 核心几何语法

- **折面**：用于品牌图形、模块封面、重要状态切换。
- **断框**：由不闭合的直角或斜切边框表达“域”和作用范围。
- **路径**：细线、短折线和方向节点表达调度、进度和关系。
- **锚点**：小圆点或方点表示状态、连接、步骤和数据落点。
- **斜切**：只在品牌级元素使用 30/45 度切角，不在每个按钮和卡片重复。

明确不使用六边形作为全局母题，也不使用蜂巢噪点、粒子雨、霓虹光晕和随机代码字符铺底。

### 3.2 Logo 建议

- 保留现有标志的 Y 形和折翼轮廓，重新绘制为可缩放的扁平矢量标志。
- 小尺寸版本只保留 2-3 个折面，不保留发光、蜂巢、细电路和照片级阴影。
- 完整插画版只用于登录页、关于页或大型活动屏。
- 标志动画采用 600-900ms 的折线汇聚与平面展开，仅在首次进入或重要品牌场景播放一次。

## 4. 设计原则

1. **简约不是空白**：保留品牌、层次和动效，但删除不能解释信息或操作的装饰。
2. **几何必须有职责**：框表示范围，线表示关系，点表示状态，面表示层级。
3. **日间优先**：先在明亮背景下解决对比、边界和密度，再映射夜间主题。
4. **内容优先于背景**：正文、题目、表格和编辑器使用稳定实体表面，背景不能穿透干扰。
5. **工作页安静，关键时刻有表现力**：高频操作使用生产性动效，模块切换和重要完成使用表达性动效。
6. **状态色语义化**：品牌色不能同时承担成功、在线、选中、进度和所有高亮。
7. **模块通过注册扩展**：赛事、培训、练习、管理等模块使用相同壳层，不硬编码导航数量。
8. **性能是视觉规范的一部分**：标准业务页不加载全屏 WebGL，不在长列表上使用大面积 backdrop blur。

## 5. 日间与夜间主题

以下颜色是方向值，正式实现前需用真实页面做 WCAG 对比度校验。

| 语义 | 建议值 | 用途 |
| --- | --- | --- |
| Canvas | `#F3F6F7` | 页面背景 |
| Surface | `#FFFFFF` | 正文、表格、主面板 |
| Surface Muted | `#E9EFF1` | 次级区域、选中前状态 |
| Border | `#C9D2D6` | 普通边界 |
| Border Strong | `#87949B` | 强调边界、焦点附近 |
| Text | `#111719` | 主文本 |
| Text Secondary | `#536066` | 次文本 |
| Brand | `#0A8F68` | 品牌、主操作 |
| Brand Soft | `#DDF4EA` | 品牌弱背景 |
| Info | `#2F6BFF` | 信息、链接、调度 |
| Warning | `#B86E00` | 警告、等待 |
| Danger | `#D6455D` | 错误、危险、删除 |

### 5.2 夜间主题

| 语义 | 建议值 | 用途 |
| --- | --- | --- |
| Canvas | `#0E1712` | 页面背景 |
| Surface | `#16221C` | 正文、表格、主面板 |
| Surface Muted | `#1D2D25` | 次级区域和辅助数据 |
| Border | `#2B3C33` | 普通边界 |
| Border Strong | `#40554A` | 焦点和强调边界 |
| Text | `#EDF5F1` | 主文本 |
| Text Secondary | `#C3D1CA` | 正文次文本 |
| Muted | `#94A69D` | 标签、时间和说明 |
| Brand | `#45C693` | 品牌、成功和局部状态 |
| Brand Soft | `#173B2C` | 品牌弱背景 |
| Runtime Surface | `#1A3026` | 运行实例和强业务摘要 |
| CTF Visual | `#214636` | CTF 赛事视觉块 |
| Exam Visual | `#294D91` | 理论考试视觉块 |

夜间主题约束：

- 夜间主题不是把 `Surface Inverse` 直接变成浅色。运行实例、赛事视觉块、练习主区和导航激活态必须使用独立语义令牌。
- 大面积区域保持深色表面，浅色只用于文字、1-3 个关键操作和小尺寸状态，不允许出现整块亮白运行卡或亮白导航块。
- 品牌绿、信息蓝和警告橙只承担局部状态，不作为大面积页面背景。
- 日间和夜间沿用相同层级关系；切换主题不能改变组件尺寸、边框数量和信息密度。

### 5.3 主题切换

- 不给所有元素添加 700ms 颜色过渡。
- 使用单个根级折面遮罩，从主题按钮方向展开，约 280-360ms 完成。
- 在遮罩覆盖期间切换令牌，避免出现整页灰色中间态。
- 不支持 View Transitions API 时退化为 180ms 根层淡化。
- `prefers-reduced-motion` 下直接切换颜色，不播放遮罩。

## 6. 字体与图标

### 6.1 字体

- 中文和普通 UI：`Inter Variable, Noto Sans SC, Microsoft YaHei, sans-serif`。
- 标题仍使用同一无衬线体系，通过字重、字号和留白建立层级，不使用特殊展示字体覆盖所有页面。
- 代码、Flag、IP、端口、时间、日志：`JetBrains Mono, IBM Plex Mono, monospace`。
- 等宽字体只用于数据和技术内容，不用于中文长正文、按钮和表单标签。
- 桌面端功能性文字不得小于 `11px`；正文、通知和操作说明不得小于 `12px`；主要按钮与列表标题建议从 `13px` 起。
- `9-10px` 仅允许用于无须阅读的装饰编号或几何标记，不能承载状态、时间、筛选、题目说明和错误信息。
- 1366px 下空间不足时优先换行、截断或调整列宽，不通过继续缩小字体解决。

### 6.2 图标

- 主图标统一使用 Lucide，常规尺寸 18/20px。
- 状态优先使用图标、颜色和文字三者中的至少两种，不能只靠颜色。
- 不使用 Emoji 作为正式状态或奖章图标。
- 相同命令始终使用相同图标，不在不同模块重复造图标语义。

## 7. 形状、表面与密度

- 基础间距为 4px，主要布局遵循 8px 网格。
- 普通控件圆角 4px，表面圆角 6px，弹层最大 8px。
- 页面区段不做漂浮卡片；卡片仅用于重复实体、弹层和真正需要边界的工具。
- 禁止卡片套卡片。内部层级使用分隔线、留白、弱底色或网格列。
- 工作页默认使用实体表面；毛玻璃仅允许出现在顶栏、命令面板或一次性覆盖层，且模糊半径受限。
- 1366px 笔记本端优先保证完整操作；1920px 以上增加列数和可用宽度，不随视口放大字体。

## 8. 全局信息架构

### 8.1 桌面端

```text
┌──────┬──────────────────────────────────────────────────────────────┐
│ 全局 │ 上下文栏：模块 / 页面标题 / 状态 / 页面操作 / [个人入口]   │
│ 栏   ├──────────────┬───────────────────────────────────────────────┤
│ 72px │ 模块侧栏     │ 主内容区                                      │
│      │ 0 / 240px    │                                               │
└──────┴──────────────┴───────────────────────────────────────────────┘
```

全局栏：

- 固定宽度为 72px，使用图标加 2-4 字短标签，不依赖 hover tooltip 才能理解。
- 默认直达模块：首页、赛事、练习、培训、战队；点击后直接导航，不先打开二级菜单。
- 顶部平台标志同时是“全部模块”抽屉触发器；低频模块和按角色出现的管理入口放入该抽屉。
- 全局栏不再承载个人入口；主题、语言和账户操作统一进入右侧个人抽屉。
- 模块由注册表生成，新增练习或其他模块不修改壳层布局。

上下文栏：

- 高度建议为 64px，显示当前模块、页面标题、关键状态和 1-3 个页面动作。
- 比赛页面可显示倒计时和阶段；课程页面显示课程名称；管理页面显示资源域。
- 最右侧固定为唯一的个人入口组件，位置不随页面动作数量变化。
- 个人入口在宽屏显示 `32px 头像 + 用户名 + 展开指示`；空间不足时只保留头像，但可访问名称始终完整。
- 页面动作与个人入口之间使用分隔线和固定间距，个人入口不混入页面命令组。
- 不把十余个管理按钮全部铺在页面顶部。

#### 8.1.1 全局栏是否抽屉化

三种方案的判断：

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 完整固定栏 | 高频模块一步到达，当前位置清楚 | 模块增加后占用高度，低频入口拥挤 | 不单独采用 |
| 所有模块都藏入抽屉 | 页面横向空间最大，结构简单 | 每次跨模块需要两步，用户难以感知当前位置和全部能力 | 桌面端不采用 |
| 固定高频栏 + 全模块抽屉 | 高频入口一步到达，低频模块可扩展，仍节省宽度 | 壳层需要维护主次模块规则 | 推荐 |

推荐的模块抽屉规则：

- 点击全局栏顶部平台标志打开左侧抽屉，宽度建议 `288-320px`；固定全局栏仍留在原位。
- 抽屉按“核心功能、学习与训练、组织协作、管理与运维”分组，显示图标、完整名称和一句状态摘要。
- 可展示最近访问的 3 个模块或未完成任务，但不能把抽屉变成第二个首页。
- 抽屉覆盖内容而不推动主布局，关闭后页面尺寸和滚动位置保持不变。
- 不使用 hover 自动展开，避免鼠标经过左侧时界面反复位移。
- 当前模块同时在固定栏和抽屉中保持激活状态，抽屉不是独立导航世界。
- 管理员可在抽屉中看到管理模块，普通用户不渲染无权限入口。

模块侧栏：

- 只在存在层级、分类或工具集合时显示。
- 用于题目分类、课程章节、练习目录、管理分组、日志筛选等。
- 1024-1279px 可折叠为抽屉或水平筛选条。

### 8.2 移动端

- 顶部 56px 上下文栏。
- 底部保留 4 个高频入口和一个“更多”入口。
- 个人头像固定在顶部上下文栏最右侧，点击打开全屏或接近全屏的个人抽屉。
- “更多”打开全模块抽屉；移动端不渲染桌面固定全局栏。
- 练习、赛事、培训的模块侧栏转换为抽屉。
- 题目提交、考试提交和实例操作始终在单手可达区域保留明确入口。

### 8.3 模块注册模型

```ts
type PlatformModule = {
  id: string
  label: string
  icon: LucideIcon
  route: string
  order: number
  placement: 'primary' | 'drawer'
  group?: 'core' | 'learning' | 'organization' | 'administration'
  description?: string
  permission?: string
  contextNavigation?: ContextNavigationFactory
}
```

“练习”模块只需注册模块定义和自身上下文导航，不应修改全局壳组件。

## 9. 动效语言

### 9.1 时间令牌

| 类型 | 时长 | 用途 |
| --- | ---: | --- |
| Instant | 80-120ms | 按压、图标反馈 |
| Fast | 160ms | Hover、焦点、状态切换 |
| Normal | 220-260ms | Tab、折叠、Popover |
| Expressive | 360-480ms | 模块切换、主题切换、重要完成 |
| Brand Intro | 600-900ms | 首次 Logo 动画，最多播放一次 |

### 9.2 页面切换

- 全局栏和上下文栏保持不动，只切换主内容。
- 同级页面：淡入 + 6-8px 横向位移，160-180ms。
- 进入详情：内容从右侧 12px 进入；返回列表方向相反。
- 模块切换：上下文栏的细路径先移动到新模块锚点，主内容随后淡入。
- 不做整页缩放、3D 翻转或长时间黑场。
- 根页面永久预留垂直滚动条槽位；不支持 `scrollbar-gutter` 时退化为始终显示纵向滚动条。
- 路由主体最小高度覆盖剩余视口，切换过程中始终只保留一个 `.route-frame`。
- 同级路由不使用“旧页面完整退出后再挂载新页面”的 `wait` 模式，避免短暂高度归零和横向宽度变化。
- 退出动画仅用于抽屉、Modal、Popover 等覆盖层；普通页面卸载时直接由新页面进入动画接管。

### 9.3 组件反馈

- 导航激活：一条 2px 信号轨移动到目标项，图标和文字颜色同步变化。
- Tab：底部轨道滑动，不重新播放整个面板动画。
- 抽屉：280ms 平移；背景只降亮度，不使用大面积强模糊。
- 数据更新：数值交叉淡化或短距离滚动，状态点只脉冲 1-3 次。
- 列表插入/删除：保留对象空间关系，使用布局动画，不让整页跳动。
- 创建实例：按钮转换为阶段进度，成功后路径从“节点”连接到“入口”，表达调度结果。

### 9.4 环境动画

- 首页、登录页、空状态和 TeamLab 概览可以使用几何环境动画。
- 普通列表和正文页背景保持静态或仅有极低频单次绘制。
- 标准业务页禁用全屏 Three.js/WebGL。
- 页面不可见、设备低性能或开启 reduced motion 时停止环境动画。

## 10. 主要页面蓝图

### 10.1 首页

- 顶部是平台身份、当前用户和一个简短动态状态，不制作营销式大 Hero。
- 第一屏直接显示“继续进行”：正在进行的比赛、最近课程、运行实例、待处理任务。
- 下方按模块展示比赛、培训、练习和平台通知。
- 几何折面只集中在品牌头部或模块切换区，不穿过所有卡片。

### 10.2 赛事列表

- 顶部筛选状态、赛制、时间和搜索。
- 进行中赛事使用较强实体行或横向卡片；历史赛事使用紧凑列表。
- 赛制、阶段、报名状态和时间是固定信息列，避免卡片高度随描述变化。

### 10.3 CTF 题目工作区

```text
比赛上下文栏：倒计时 / 进度 / 题目 / 榜单 / 监控
┌────────────────┬──────────────────────────┬────────────────┐
│ 题目库         │ 题目正文与解题操作       │ 比赛上下文     │
│ 搜索/分类/列表 │ 题面/附件/实例/Flag      │ 队伍/通知/提交 │
│ 280-320px      │ min 460px / 1fr          │ 280-310px      │
└────────────────┴──────────────────────────┴────────────────┘
```

- 左栏合并分类筛选与题目列表，不再使用“分类栏 + 列表栏 + 最右正文”的三段导航结构。
- 分类可能达到 6-10 种或更多，使用可折叠分类树：默认展开当前题型，各分类可独立并行展开，搜索时临时展开含匹配结果的分类；不使用固定五列按钮或隐藏层级的单一下拉框。
- 展开关系由一条清晰的中性垂直轨道表达，建议 `2px`；不再叠加绿色侧条、圆环节点等重复层级装饰。
- 分类行与题目子项使用同一高度基线，题目子项不得比上层分类行更高或更宽，只通过缩进和轨道体现从属关系。
- 正文位于页面中央并获得最大弹性宽度，标题、Markdown 题面、目标、附件、实例和 Flag 形成连续解题路径。
- 实例与 Flag 必须位于附件之后，符合“理解题面 → 获取附件 → 创建环境 → 提交结果”的任务顺序。
- 右栏只承载队伍摘要、比赛通知和最近提交等上下文信息，不能承载长题面或核心解题操作。
- 题目行固定高度，分类色仅用于小标签、状态点和边缘状态。
- 选中题目写入 `?challenge={id}`，切换题目只更新正文和右栏状态，不重排三栏骨架。
- `ChallengeWorkbench` 仍作为领域组件复用，但正文区、运行区和比赛上下文由宿主明确分槽，不能自由堆叠。
- 1024px 以下右栏下移为双列辅助区；768px 以下题目库、正文和操作区按顺序转为单栏。

### 10.4 理论考试

- 一次只展示一道题。
- 右侧为题号索引，顶部为进度、剩余时间和草稿状态。
- 最终提交使用独立确认步骤，明确“提交后不可修改”。
- 夜间主题不降低选项、选中态和错误反馈的可读性。

### 10.5 AWDP

- 顶部使用阶段时间轴表达准备、攻击、修补和结束。
- 服务、队伍、Checker、Flag 和得分使用状态矩阵，不依赖长段文字。
- 攻击入口、补丁上传、重置和恢复动作放在与当前阶段一致的操作区。
- 阶段切换属于表达性动效，可用折面推进一次，但不能持续闪烁。

### 10.6 培训首页与课程详情

- 培训首页保留课程海报、最近学习/授课课程和全部课程，但用稳定比例网格。
- 课程详情顶部为海报、课程信息和主操作；下方使用标签或模块侧栏组织内容。
- 学生状态与教师管理使用同一数据模型，不在一个页面复制两套组件。
- 教师编辑页采用“左侧编辑 / 右侧预览”的独立工作台。

### 10.7 章节详情

```text
┌──────────────┬──────────────────────────────┬────────────┐
│ 章节树       │ 正文 / 视频 / 实验 / 作业    │ 文档目录   │
│ 240px        │ 680-900px                    │ 200px      │
└──────────────┴──────────────────────────────┴────────────┘
```

- 正文宽度受控，左右栏不压缩阅读区。
- 实例和 Flag 区在章节内容末尾使用独立工具表面。
- 右侧目录只跟随正文标题，不承担课程导航。

### 10.8 练习模块

练习是当前一级模块，正式路由包含四个页面：

1. **练习首页** `/practice`：最近练习、推荐题单、分类入口、连续学习和个人进度。
2. **题库列表** `/practice/browse`：分类、难度、标签、状态、来源和搜索。
3. **单题工作区** `/practice/challenge/:id`：题面、附件、实例、Flag/答案、提示和提交结果。
4. **统计中心** `/practice/stats`：分类分布、趋势和完成情况。

练习可以复用 `ChallengeWorkbench` 的领域无关展示和运行控制，但比赛得分、比赛阶段和赛内动态不得进入练习事实。收藏、题单和更细复盘能力仍属于已知缺口。

### 10.9 个人用户页

个人页不是账户编辑表单，而是用户在平台中的公开身份、成长记录和业务经历汇总。账户资料编辑继续放在独立设置页，避免公开信息与敏感资料混在一个界面。

建议路由：

- `/users/:userId`：公开用户页。
- `/users/me`：跳转到当前用户的公开页，并显示本人专属操作。
- `/settings/profile`：头像、用户名、简介、真实姓名、学号、邮箱、手机号和隐私设置。
- 原 `/account/profile` 可在新前端中重定向到 `/settings/profile`，不要求后端立即改名。

用户入口：

- 上下文栏最右侧只保留一个个人入口组件，不把“我的主页”和“账户设置”拆成两个全局入口。
- 点击个人入口后打开右侧个人抽屉，在同一处提供个人摘要、继续进行和账户相关命令。
- 队伍成员、排行榜提交者、课程教师和允许公开的参赛记录中的用户名均可进入公开页。
- 教师在课程内查看学员详情仍使用课程权限页面，不借公开个人页绕过课程数据边界。

#### 10.9.1 个人入口与账户抽屉

个人入口组件 `AccountTrigger`：

- 始终位于上下文栏最右侧，不进入全局栏，也不随页面内容滚动。
- 宽屏显示头像、用户名和向下指示；用户名最大宽度为 `120px`，超出使用省略号。
- `1024px` 以下只显示头像与未读状态点，不改变上下文栏其他元素位置。
- 未登录时同一位置显示“登录”命令，不保留空头像占位。
- 点击、`Enter` 或 `Space` 打开右侧 `AccountDrawer`；再次点击、按 `Esc` 或点击遮罩关闭。

右侧个人抽屉建议宽度为 `clamp(320px, 24vw, 380px)`，包含以下稳定区域：

```text
┌────────────────────────────────┐
│ 头像  用户名  角色        关闭 │
│ 简介或当前身份                  │
├────────────────────────────────┤
│ 解题数    活跃天数    运行实例 │
├────────────────────────────────┤
│ 继续进行                        │
│ 最近课程 / 当前比赛 / 运行实例 │
├────────────────────────────────┤
│ 个人主页                        │
│ 账户设置                        │
│ 我的队伍 / 我的课程             │
│ 按角色出现的管理入口            │
├────────────────────────────────┤
│ 主题  语言              退出登录│
└────────────────────────────────┘
```

- 顶部只展示公开身份字段，不在抽屉中显示邮箱、手机号、学号或 IP。
- 摘要默认使用“个人解题、活跃天数、运行实例”三项；教师可将第三项替换为待审核事项，管理员只显示必要告警数，不复制管理仪表盘。
- “继续进行”最多展示 3 项，优先级为即将结束的考试或比赛、运行实例、最近课程。
- “个人主页”和“账户设置”仍是不同路由，但由同一个抽屉统一承载，用户不需要理解两个全局入口。
- 我的队伍、授课课程、API Token 和管理入口按角色与权限显示，不渲染禁用占位项。
- 主题和语言使用图标加当前值；退出登录位于固定底部，不能随内容滚出可视区。
- 抽屉使用 `height: 100dvh` 和 `grid-template-rows: auto minmax(0, 1fr) auto`；中间内容独立纵向滚动，禁止产生水平滚动条。
- 桌面端抽屉覆盖页面而不挤压主内容；背景只降低亮度，不使用强模糊。移动端宽度为 `100vw`，保留明确返回和关闭方式。
- 打开后焦点进入抽屉，关闭时返回 `AccountTrigger`；屏幕阅读器读取标题“个人与账户”。

建议新增轻量摘要接口，避免打开抽屉时请求完整个人页：

```text
GET /api/account/summary
```

响应只包含身份摘要、三项统计、最多三条继续进行事项、未读数量和有权限的快捷入口。该接口可短时缓存，但运行实例和倒计时需要单独刷新或通过现有实时通道更新。

#### 10.9.2 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 身份横幅：头像 / 用户名 / 角色 / 简介 / 本人操作            │
├──────────────────────────────────────────────────────────────┤
│ 解题数   提交数   正确率   参赛场次   已学课程   活跃天数    │
├────────────────────────────────────────┬─────────────────────┤
│ 概览 / 做题 / 赛事 / 培训              │ 身份事实            │
│                                        │ 加入时间            │
│ 活跃热力图                             │ 公开队伍            │
│ 分类解题画像：雷达 + 真实数据表        │ 授课课程或角色信息  │
│ 成长趋势                               │                     │
│ 参赛、结课和里程碑时间线               │                     │
└────────────────────────────────────────┴─────────────────────┘
```

- 页面最大内容宽度建议为 `1240-1320px`，主栏与辅助栏约为 `minmax(0, 1fr) / 300px`。
- 身份横幅是一个完整页面区段，不放进悬浮卡片。首版使用基于用户 ID 稳定生成的折面和路径背景，不依赖尚未存在的自定义封面字段。
- 头像与用户名必须保持第一视觉层级；角色只是紧邻用户名的小型语义标签，不使用夸张勋章造型。
- 简介最多显示三行，空简介使用低强调占位，不让身份区高度因长文本失控。
- 本人显示“编辑资料”；其他用户不显示不存在的关注、私信或举报能力。
- 汇总数字采用洛谷式横向信息带，但不使用“全局排名”和“综合分”这类当前没有统一语义的数据。
- 标签切换只替换主内容，身份横幅、汇总数字和右侧身份事实保持稳定。

标签职责：

- **概览**：热力图、分类画像摘要、成长趋势和最近经历。
- **做题**：完整分类数据、解题趋势和可公开的历史记录；不展示 Flag、答案或比赛未结束题目。
- **赛事**：参赛时间线、赛制、队伍和随队结果，明确标注“团队成绩”。
- **培训**：本人查看课程进度、理论作业和章节完成情况；公开访客只看到用户主动公开的汇总或授课课程。

#### 10.9.3 汇总数字

首版建议固定六项：

1. **个人解题**：由该用户亲自提交并判定正确的不同题目数。
2. **提交**：可计入做题统计的个人提交总数。
3. **正确率**：正确提交数除以可判定提交数，旁边保留样本数提示。
4. **参赛场次**：状态有效且比赛允许公开的参与记录数。
5. **已学课程**：审核通过的课程数；本人可展开查看完成数量。
6. **活跃天数**：当前统计窗口内存在有效学习或竞赛事件的自然日数。

不要把以下数据混入“个人解题”：

- 队友提交成功后带来的队伍解题记录。
- `FirstSolve` 中只有队伍参与关系、无法证明个人提交者的记录。
- AWDP 的 SLA、修补和服务分等团队得分。
- 理论考试分数、培训进度和签到次数。

#### 10.9.4 活跃热力图

- 默认展示最近 52 周，可切换自然年；使用固定单元格 CSS Grid，不使用持续 Canvas。
- 热力图表达活动量而不是能力分，颜色强度按每日有效事件数分档并设置上限。
- Tooltip 展示日期及 CTF 提交、培训提交、理论交卷、章节完成、AWDP 攻击成功、渗透得分等分类明细。
- `TrainingCheckIn` 可作为培训活动补充，但不能成为全平台活跃度的唯一来源。
- 公开视图只返回按日聚合数字；本人视图可进入具体记录。

#### 10.9.5 分类解题画像

雷达图名称使用“分类解题画像”，不直接命名为不可解释的“综合能力”。维度由注册表配置，首版建议固定为：

- Web
- Pwn
- Reverse
- Crypto
- Forensics / IR
- Pentest / OSINT
- Misc / AI / PPC
- Other：Blockchain、Hardware、Mobile 及后续低题量分类

维度映射不能散落在页面组件中，应由 `SkillDimensionRegistry` 统一维护，后续练习模块与比赛、培训共用同一分类口径。

每个维度必须提供四个真实值：

- `solved`：不同题目中至少一次正确的数量。
- `attempted`：有过可判定提交的不同题目数量。
- `submissions`：可判定提交总数。
- `successRate`：正确提交数 / 可判定提交数。

雷达图只用于比较分类广度，建议使用平台基准归一化：

```text
benchmark(c) = max(5, 最近 365 天活跃用户在分类 c 的个人解题数 P90)
radar(c) = clamp(0, 100, 100 * log(1 + solved(c)) / log(1 + benchmark(c)))
```

- 该算法比“用户自身最强项固定为 90”更稳定，不会因只做一个分类就画出满轴。
- 雷达旁始终显示真实数据表；Hover 或键盘聚焦维度时同步高亮对应表格行。
- 少于 3 道尝试题时标记“样本不足”，不隐藏数据，但降低填充强调。
- 正确率不直接叠加进雷达，避免少量提交的 100% 正确率压过长期解题广度。
- 移动端和 200% 缩放下将雷达替换为横向条形维度列表，不能要求左右拖动图表。

统计事实键应包含业务场景，例如 `(game, gameChallengeId)`、`(training, exerciseChallengeId)`、`(practice, exerciseChallengeId)`，避免事件和不同领域 ID 碰撞。汇总时另设规范题目键：比赛题使用 `gameChallenge:{id}`，课程与未来练习共用的题目使用 `exerciseChallenge:{id}`。这样同一道练习题在不同场景完成时，汇总数字只计算一次，历史记录仍保留每个场景来源。

#### 10.9.6 成长趋势与经历

- 成长趋势默认展示累计个人解题数，允许切换最近 90 天；一次最多选择四个分类，避免 NSSCTF 式多线重叠。
- 趋势图使用轻量 SVG，Hover 显示日期、累计值和当天新增，不在每次 Tab 切换时重新播放完整绘制动画。
- 经历时间线复用 HGame 的简洁事件结构，但内容扩展为参赛、结课、课程授课和可验证里程碑。
- 比赛结果显示比赛名、赛制、队伍、结束时间和随队名次/分数，并明确标记“团队成绩”。
- 理论考试个人分数、培训作业答案和课程内详细进度默认不进入公开时间线。

#### 10.9.7 现有数据映射

| 展示内容 | 当前数据来源 | 使用边界 |
| --- | --- | --- |
| 用户名、角色、简介、头像 | `UserInfo` | 可公开 |
| 加入平台时间 | `UserInfo.RegisterTimeUtc` | 公开到月份或日期，不公开登录时间与 IP |
| CTF 个人提交与分类 | `Submission` + `GameChallenge` | 仅 `UserId` 对应提交者；排除测试、隐藏和未结束比赛的敏感明细 |
| 队伍解题与比赛结果 | `UserParticipation` + `Participation` + `FirstSolve` | 只作为团队经历，不计入个人解题 |
| 培训实例题 | `TrainingCourseSubmission` + `ExerciseChallenge` | 公开只给汇总；本人和课程教师按权限查看详情 |
| 培训进度 | `TrainingCourseProgress` + `TrainingChapterProgress` | 默认本人可见 |
| 课程理论作业 | `TrainingCourseChapterTheorySheet` + Answers | 分数和对错详情默认本人及课程授权教师可见 |
| 比赛理论考试 | `TheoryAnswerSheet` + `TheorySubmissionAnswer` | 不进入实战雷达，个人分数默认非公开 |
| AWDP 攻击成功 | `AwdpFlag.SubmittedByUserId` | 可形成个人攻击命中数 |
| AWDP 修补、SLA 与服务分 | `AwdpPatchSubmission`、Checker、队伍分 | 当前修补记录无用户 ID，只能显示团队结果 |
| 渗透测试提交 | `PenetrationSubmission.UserId` | 单独形成渗透经历，不混入普通 CTF 成功率 |
| 自主练习 | Exercise 模块的练习题、提交与统计接口 | 只展示服务端可审计的个人练习事实，不从比赛临时状态推导 |

当前 `ProfileUserInfoModel` 只适合本人资料编辑，不能直接作为公开个人页 DTO。新前端应增加只读聚合模型，避免误返回邮箱、手机号、真实姓名、学号、IP 和登录时间。

#### 10.9.8 权限与隐私

| 数据 | 公开访客 | 本人 | 课程教师 | 管理员 |
| --- | --- | --- | --- | --- |
| 用户名、头像、简介、角色 | 可见 | 可见 | 可见 | 可见 |
| 邮箱、手机号、真实姓名、学号 | 不可见 | 可见并可编辑 | 仅课程既有授权页面按需可见 | 管理后台可见 |
| 最近登录、IP、IAM 绑定 | 不可见 | IAM 状态可见，IP 不显示 | 不可见 | 管理后台按权限可见 |
| CTF 分类汇总 | 可见 | 可见 | 可见 | 可见 |
| 未结束比赛明细 | 不可见 | 仅当前用户原有业务入口可见 | 不因教师角色额外可见 | 按比赛管理权限可见 |
| 培训详细进度与作业答案 | 不可见 | 可见 | 仅其授课课程内可见 | 可见 |
| 理论考试个人分数 | 默认不可见 | 可见 | 课程理论按课程权限可见 | 可见 |

如果后续增加隐私开关，建议使用字段级策略而不是一个“隐藏全部”开关。公开页服务端必须完成裁剪，不能只在前端隐藏敏感字段。

#### 10.9.9 建议 API 与聚合边界

建议由独立的 `UserProfileQueryService` 聚合只读数据，页面不直接并发访问六个业务控制器：

```text
GET /api/users/{userId}
GET /api/users/{userId}/overview?window=365d
GET /api/users/{userId}/activity?from=2025-07-01&to=2026-07-01
GET /api/users/{userId}/history?type=competition&cursor=...
GET /api/users/me/private-overview
```

- `users/{id}` 仅返回公开身份字段。
- `overview` 一次返回汇总数字、分类真实值、雷达基准和轻量趋势，减少首屏请求瀑布。
- 热力图与长历史记录延迟加载并按时间窗查询。
- 公共聚合可缓存 5 分钟并使用 ETag；本人敏感数据不进入公共缓存。
- 查询必须优先使用当前已有的 `UserId`、`SubmittedAt/SubmitTimeUtc` 和分类索引。数据量增长后再增加每日聚合表，首版不必先建通用事件总线。

建议响应的分类项保持可解释：

```ts
type UserSkillDimension = {
  id: string
  label: string
  solved: number
  attempted: number
  submissions: number
  acceptedSubmissions: number
  successRate: number
  benchmarkP90: number
  radarValue: number
  sampleSufficient: boolean
}
```

#### 10.9.10 动效与响应式

- 进入用户页时，身份横幅中的折线路径绘制一次，时长 `360-480ms`；头像和文字直接出现，不等待背景动画结束。
- 标签激活轨道使用 `160-220ms` 位移；内容只做 8px 淡入，不整页缩放。
- 雷达由中心到目标值绘制一次，筛选时在旧形状与新形状之间插值；开启 reduced motion 时直接切换。
- 统计数字不使用长时间滚动计数，以免每次返回页面都产生噪声。
- `>= 1280px` 使用主辅双栏；`768-1279px` 将身份事实移到主内容下方；`< 768px` 使用单栏，汇总数字为 2 或 3 列稳定网格。
- 头像、身份文本、统计带和标签必须设置稳定尺寸，异步数据到达后不能推动整个页面跳动。

### 10.10 管理与节点页

- 管理模块使用分组侧栏：内容、资源、用户、运维、系统。
- 节点页优先使用资源表格/紧凑节点行；只有需要对比资源构成时才使用卡片。
- 在线状态、调度状态、容量、端口池和隧道健康度形成固定列。
- 详情使用右侧抽屉，不在列表下方无限追加巨型详情区。

### 10.11 TeamLab / 拓扑工作区

- 这是允许全屏画布的特殊页面。
- 画布无装饰卡片外框，工具栏、属性面板和运行观测面板浮在画布边缘。
- 几何动画必须表达节点连接、流量、部署或异常，不做纯背景动画。

规则：

## 12. 性能与可访问性预算

### 12.1 性能

- 标准页面首屏不加载 Three.js、GSAP、ECharts、PDF 或 Shiki。
- 个人页雷达、趋势和热力图优先使用轻量 SVG/CSS Grid；统计标签延迟加载，不为一个雷达图引入完整图表框架。
- 标准路由 chunk 建议不超过 250 KiB gzip；特殊拓扑/大屏单独预算。
- 业务滚动区不使用大面积 `backdrop-filter`、`mix-blend-mode` 或持续滤镜。
- 进入页面 150ms 内没有完成加载时显示保持布局的 Skeleton，不显示空白背景。
- 路由和抽屉动画以 transform/opacity 为主，目标为 60fps。
- 长列表分页或虚拟化；不可因动画关闭虚拟化。

### 12.2 可访问性

- 正文、控件和状态达到 WCAG AA 对比度。
- 所有操作支持键盘焦点，焦点环不被几何装饰遮挡。
- 状态不只依赖颜色。
- 支持 `prefers-reduced-motion`、高对比度和 200% 页面缩放。
- 360px 下保留查看、答题、提交和实例操作，不以“屏幕太窄”拒绝使用。

## 13. 禁用清单

- 六边形、蜂巢、代码雨或随机字符作为全站背景。
- 暗色主题作为唯一设计基准。
- 全站霓虹绿、青绿色或紫色单色统治。
- 全站中文使用等宽字体。
- 页面级全屏 WebGL 背景。
- 长列表表面使用强毛玻璃和多层滤镜。
- `transition: all`、全局逐元素主题渐变和无限高频动画。
- 卡片套卡片、页面区段全部卡片化、按钮全部胶囊化。
- 用大标题、大片留白和装饰图代替真实业务内容。
- 为增加新模块修改固定宽度或硬编码数量的导航。

## 15. 设计结论

YINYU vNext 不应成为 HGame 的换标版本，也不应继续旧版“深色 + 霓虹 + 毛玻璃”的路线。推荐以“折域”为独立母题：用折面建立品牌，用断框表达范围，用路径表达关系，用锚点表达状态；日间主题负责证明信息架构和对比度，夜间主题负责延续专业氛围。复杂工作页接近 Linear/Carbon 的克制，首页和重要切换才使用 HGame、Vercel 一类有辨识度的几何动画。

## 16. 2026-07-13 设计反馈确认

以下三项作为后续开发基线，不再视为单页补丁：

1. **CTF 工作区采用“题目库 / 正文与解题操作 / 比赛上下文”结构**。正文、附件、实例和 Flag 位于中央主栏，队伍信息、比赛通知和最近提交进入右侧辅助栏。
2. **夜间主题采用语义色映射**。禁止通过大面积浅色反转制造对比，运行区、赛事视觉和导航激活态各自使用专用令牌。
3. **路由切换优先保持空间稳定**。滚动条槽位、主内容最小高度和单路由帧是强制规则，页面表达性动画不得引发布局抖动。

反馈原型只作为问题诊断和布局参考；正式实现继续沿用 YINYU 的简约几何语言、8px 网格、Lucide 图标和克制动效，不复制反馈稿的独立品牌细节。
