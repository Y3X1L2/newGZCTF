# TeamLab 接入 Netlab

## 目标与边界

基线为远端 main `ce1ef4ec`。组网生命周期、物理资源调度和观测交给 Netlab 公共 API；newGZCTF 保留用户、比赛、队伍、目标、计分及使用权限。前端使用 Netlab 正式嵌入工作区，统一服务端代理，复用同一份前端制品。用户授权两人分工；验收覆盖调用链、权限和界面流程，底座并发调度属于底座验收范围。

## 分工

- 集成负责人：`codex/netlab-integration`，后端接口、业务关联、迁移、旧执行链清理和最终检查。
- 前端：`codex/netlab-workspace`，vNext 宿主、管理与选手入口、旧页面清理；Netlab `codex/upstream-integration` 的 `web/` 由同一前端负责人修改。
- Netlab 后端和公共契约由集成负责人修改；生成代码通过源契约生成。

## 实施顺序

1. 固定公共调用契约、配置化连接与单一业务授权，建立 API、SSE、WebSocket 和文件流通道。
2. 复用底座环境、模板和工作区，替换上层管理与选手入口。
3. 将比赛场景及队伍环境关联迁移为底座稳定标识，目标与计分继续由上层处理。
4. 按用户确认将现有场景、镜像和运行实例迁移留到上线阶段；本次保留历史数据与引用，完成前向数据库迁移。
5. 删除已替代的组网执行链、状态流转、页面、接口和仅覆盖旧实现的测试。
6. 检查权限隔离、生命周期调用、断线任务读取、界面交互及构建；形成真实执行记录。

## 契约

- `GET /api/teamlab/workspace[?gameId=...]` 返回连接状态和已授权工作区入口。
- `/api/teamlab/netlab/` 为受控同源代理，API 沿用底座 `/api/v1` 契约，服务凭据仅留服务端。
- 上层用户权限收敛在业务入口。底座服务身份限定接入范围，请求上下文进一步收窄可操作资源。
- 工作区 HTML 接收服务端注入的可信基址与主题；底座独立账号和授权入口由宿主统一承担。
