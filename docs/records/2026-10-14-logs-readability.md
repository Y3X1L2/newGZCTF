## 已核对的问题

1. 前端 `adminLogPresentation.ts` 将原始 level/status 直接当标签，资源退回 ID/eventCode；`AdminLogDrawer.tsx` 用 eventCode 作标题，并无条件展示错误与技术字段。
2. `/admin/logs` 读取 Logs；结构化运行事件先写 OperationalEvent，再经日志 writer 派生系统日志。派生路径没有完整传递已有身份、资源快照及结果语义，factory 默认 Anonymous。
3. 节点名称查询与事件快照能力已存在，但系统日志查询未完整利用。必须分别验证历史列表、实时流与展开详情，不能只修复一条显示路径。
4. 用户截图作为问题证据；本任务尚未连接生产或读取生产日志，代码结论不能替代部署后的现场验收。

## 改造方案与不变量

| 层次 | 方案 | 事实约束 |
| --- | --- | --- |
| 写入与查询 | 保留可信操作者、来源、对象显示快照与原始 outcome；批量补足可查名称 | 历史身份/IP 缺失不猜测；当前名称不能伪装成历史快照 |
| 日常列表 | 时间、操作人、可读动作、对象、结果；事件/级别/资源类型本地化 | 未知事件有保守回退；Observed 不等于操作成功 |
| 展开详情 | 可读摘要和上下文优先；失败/受阻才出现诊断区 | 保留错误代码、可重试事实和定位证据，缺失原因明确说明 |
| 技术信息 | 折叠展示 eventCode、UUID、关联/追踪 ID、原始正文 | 不删除诊断事实，不以机器 ID 占据默认标题 |
| 运维定位 | 保留筛选、分页、实时增量及关联链路 | 同一 correlation 不证明同一操作者，不按关联 ID 粗暴回填 |

优先复用现有数据结构；是否需要迁移以完整持久化和准确历史读取为准，不为避免迁移牺牲事实。跨模块名称解析遵守 query contract，避免逐条请求和 N+1 查询。所有新增正文和字段继续服从脱敏白名单。
