## 已核对的问题

1. 前端 `adminLogPresentation.ts` 将原始 level/status 直接当标签，资源退回 ID/eventCode；`AdminLogDrawer.tsx` 用 eventCode 作标题，并无条件展示错误与技术字段。
2. `/admin/logs` 读取 Logs；结构化运行事件先写 OperationalEvent，再经日志 writer 派生系统日志。派生路径没有完整传递已有身份、资源快照及结果语义，factory 默认 Anonymous。
3. 节点名称查询与事件快照能力已存在，但系统日志查询未完整利用。必须分别验证历史列表、实时流与展开详情，不能只修复一条显示路径。
4. 用户截图作为问题证据；本任务只读核对生产服务与接口授权状态，未读取认证后的生产日志。代码结论不能替代部署后的现场验收。
5. `LogModelFactory` 未指定 Status 时默认 Success，不能准确表达 Observed、Pending、Blocked 等结果；SignalR 在持久化前发送的 Id 默认为 0，前端去重会丢弃后续实时记录。
6. 管理 mutation action filter 在响应结果执行前读取 HTTP 状态，存在错误结果仍审计为成功的风险；任意 Guid 路由 id 被当成节点维度也需收紧。
7. 现行 vNext `/admin/logs` 只有系统日志页面；运维手册中“事件时间线”“恢复漂移”标签的描述与路由不符，本任务同步修正。
8. 能力 manifest/hash 包含可用磁盘，容量波动触发 `node.capability.changed`；节点更新方法的返回值还混入 Fabric 健康变化。保留容量保存与协议 hash，单独比较稳定能力来决定是否写事件，删除错误噪声来源。

## 改造方案与不变量

| 层次 | 方案 | 事实约束 |
| --- | --- | --- |
| 写入与查询 | 保留可信操作者、来源、对象显示快照与原始 outcome；批量补足可查名称 | 历史身份/IP 缺失不猜测；当前名称不能伪装成历史快照 |
| 日常列表 | 时间、操作人、可读动作、对象、结果；事件/级别/资源类型本地化 | 未知事件有保守回退；Observed 不等于操作成功 |
| 展开详情 | 可读摘要和上下文优先；失败/受阻才出现诊断区 | 保留错误代码、可重试事实和定位证据，缺失原因明确说明 |
| 技术信息 | 列表隐藏 eventCode、UUID 和关联/追踪 ID；抽屉底部直接列有值的技术信息 | 抽屉不再二级展开，不重复原始整包，不以机器 ID 占据标题 |
| 运维定位 | 保留筛选、分页、实时增量及关联链路 | 同一 correlation 不证明同一操作者，不按关联 ID 粗暴回填 |

Logs 目前没有准确事件关联或诊断 JSON 字段。为保证持久化列表和实时流一致，决定新增可空的 actor、outcome、retryable、detail 字段，使用前向迁移，历史数据不猜测回填。跨模块名称解析遵守 query contract，避免逐条请求和 N+1 查询。所有新增正文和字段继续服从脱敏白名单。

用户追加约束：删除已证实错误和冗余设计，说明去除原因；实现保持简洁，不新增日志框架或复杂兼容推断。替换旧默认值和展示逻辑，不让新旧两套实现并存。保留诊断字段不等于在首屏重复展示；必要抽象只围绕当前调用链。

详情交互按用户最新反馈收敛：抽屉已经是展开层，不再添加二级折叠。可读摘要、异常诊断和底部技术信息直接按顺序展示，省略空字段；长原始文本限制高度以便阅读。

### 去除的旧设计及原因

| 去除或替换 | 原因 |
| --- | --- |
| 未指定结果时默认 Success | 未抛异常不证明操作成功，观察/排队/受阻必须保留自己的结果 |
| 用户、节点与 IP 混作单一“来源” | 三者职责不同，混用导致后台事件看成匿名用户、节点地址看成请求 IP |
| 事件代码与 UUID 占据主要标题 | 不能解释动作和对象；保留在技术信息即可 |
| 正常日志固定显示空错误字段、重复原始整包 | 增加阅读负担而没有诊断价值；只在有异常时显示相关诊断 |
| 所有实时记录都用未入库 id=0 去重 | 第二条起会丢失；入库前后按各自可用标识匹配 |
| 用完整能力 hash 或 Fabric 更新结果触发能力变化事件 | 剩余磁盘和网络健康波动不等于稳定能力改变；容量保存继续正常执行 |
| 运维手册中不存在的页面标签 | 与正式 vNext 路由不符，改为真实页面与受授权 API 入口 |
