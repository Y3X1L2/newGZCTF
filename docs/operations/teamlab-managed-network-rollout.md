## 可复现步骤（本次已按限定范围执行）

1. **确认现场和维护窗口。** 读取软链接、服务参数、当前迁移头、节点库存、排队及执行任务；核对存储和镜像分布。暂停新的部署操作，等待无法中断的任务结束。已有QEMU/Docker业务进程不自动销毁。
2. **保留可恢复事实。** 在服务器独立备份目录保存完整数据库备份、迁移版本、当前配置/附件和原Agent；检查非零大小、摘要及备份可读取。配置备份采用受限权限，不把秘密写进报告。旧release继续保留。
3. **上传并核验。** 解包到 `/opt/gzctf/releases/teamlab-managed-<SHA>/publish`，逐文件验签；连接既有共享附件目录，保留实际运行配置。包内Agent必须和manifest一致。
4. **前向迁移。** 只有现场迁移头匹配已验收基线 `20260927121625_AddTeamLabNetworkDnsAsset` 才执行本包SQL；不匹配则先核对差异。新迁移 `20261001145237_AddTeamLabManagedGuestNetwork` 添加五个可空字段，不重写旧release和旧计划。迁移失败不切换版本。
5. **切换主站与本机Agent。** 短暂停止相关服务，以临时软链接加原子rename切换主站；本机Agent使用独立版本文件/原子替换，保留旧执行文件和配置。启动后核对活动目录、摘要、健康端点、日志和迁移头，不以active代替完整验收。
6. **同步相关Worker。** 用正常节点同步入口逐个更新Agent，核对实际心跳二进制SHA和能力，不仅看数据库缓存摘要。现有同步流程会暂时限制节点调度；禁止省略Fabric验证或在失败后强行改数据库恢复调度。先确认更新前后的主机网络配置保持当前意图，不新增公网转发或重建既有网段。
7. **独立实机验收。** 按下表创建、重置、销毁本次专用实例，不操作保留教学runtime；需要组件时只准备独立镜像副本，并登记新模板。原始VM118–121与raw模板不改写。

## 实机验收清单

| 场景 | 通过条件 |
| --- | --- |
| 既有单网卡DHCP | 正常创建、获取实际IP/DNS、远程登录、重置仍正确、销毁无残留 |
| Linux双网卡静态 | 两张卡按MAC对应不同网段；地址/掩码/无网关/无DNS正确，无额外跨段互通 |
| 现代Windows静态 | 新网卡自动取到计划IP/DNS；RDP、域解析、普通域用户登录、重置恢复通过 |
| Server2008R2 | 实际QGA/驱动/PowerShell兼容执行与回读；缺组件应明确失败，不能冒充支持通过 |
| 多卡路由 | 只改声明的卡，默认网关数量正确，静态route metric回读一致，重复执行不重建已正确配置 |
| 缺件和漂移 | 缺QGA或脚本输入能力、工具/驱动缺失、回读不一致都显示真实失败阶段 |
| 两份实例及清理 | 使用当前地址分配约束允许的独立地址/范围验隔离；一份销毁不影响另一份；域/磁盘/端口按归属回收 |

本轮不实现固定IP原样多副本的VRF/地址池重设计；如当前地址池无法原样并行复制，记录限制，不换成只看进程的验收。域信任与业务文件权限属于网络完成后的业务检查，不由网络执行器自动重新加域。

主站和承载新场景的全部Agent需要相应版本。ManagedStatic有明确能力门禁；进阶逐卡DHCP策略没有单独的旧Agent能力标记，因此不能在未更新的网络owner/Worker上发布该类新场景。本次已在`.27`完成验收，相关新场景仍限定该节点；混用版本不记录为已支持。

## 回退

主站无法启动、迁移失败、节点/队列事实异常、网络验证失败或隔离失败时停止新增测试并回退。主站软链接切回保留的旧release，本机及已同步Worker恢复原Agent和配置；重新核对首页、登录、迁移、节点和保留实例可访问性。

新增列可供旧应用忽略，应用回退默认保留已成功添加的列。禁止执行Down删除新场景配置或删除迁移记录。如确需整库恢复，使用完整备份并明确停止写入，记录数据处理范围。只销毁本次专用测试资源，保留所有源镜像和生产备份。

旧版本不能执行新ManagedStatic计划。回退前停止这批新版本的待执行/恢复任务，并通过正常流程回收专用测试实例；不要恢复新功能场景的调度，直到新版本再次完成验收。保留新增数据不等于旧应用支持运行新配置。
