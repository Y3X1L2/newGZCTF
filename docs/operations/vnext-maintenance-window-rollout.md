# YINYU 生产发布与回滚手册

更新时间：2026-08-16

本文是生产发布的现行操作入口。服务器地址、服务名、数据库容器名和发布版本必须在执行前从目标环境读取，不把某次发布的固定值当作永久事实。

## 1. 发布前检查

1. 确认发布 SHA 已推送到远端，工作树干净，当前分支与目标分支关系明确。
2. 阅读 `docs/development/current-state.md`，确认本次改动涉及的迁移、节点、镜像、Agent、网关和业务链路。
3. 确认维护窗口、执行人、验收人和回退决策人。
4. 确认旧发布目录、当前软链接、配置文件、文件存储、数据库和网关配置的真实位置。
5. 确认没有正在运行的不可中断业务；必须停止的实例、队列或节点操作先记录并通知使用者。
6. 使用本地磁盘存储时，确认 `/opt/gzctf/shared/files` 存在，并且当前 `publish/files` 最终解析到该目录；禁止把附件保存在单个 release 目录。

## 2. 必须备份的内容

发布前在目标服务器保存一份带时间戳的备份目录，至少包含：

- PostgreSQL 完整逻辑备份和迁移版本；
- 上传文件、附件、镜像元数据和必要的运行配置；
- 当前发布目录及其 Git SHA；
- Nginx/公网入口配置、端口映射和 ACK 状态；
- 主站与 Agent 的服务配置和启动参数，不包含密码、Token、Cookie 或私钥明文。

备份完成后必须实际检查文件存在、大小非零，并记录校验摘要。不能用“备份命令返回成功”替代检查。

## 3. 构建和发布物

在开发机执行最小门禁：

```powershell
git status --short --branch
git fetch origin --prune
git diff --check
dotnet build src/GZCTF.slnx -c Release
dotnet test src/GZCTF.Test/GZCTF.Test.csproj -c Release
```

前端或共享契约变化时，再执行 `src/GZCTF/ClientApp` 下的 locale、lint、TypeScript、架构检查、测试和 `pnpm build`。真实 Docker/KVM/Agent/网关链路不能由本地 mock 代替。

发布物使用完整 SHA 命名，并放入新的 release 目录。禁止原地覆盖当前运行目录，禁止使用仓库中的历史一键部署脚本。

## 4. 数据库迁移

1. 发布前记录当前迁移头。
2. 先在数据库副本或可恢复环境执行同一迁移命令，检查用户、战队、赛事、课程、答卷、镜像、节点、AWDP、TeamLab 和练习数据。
3. 生产窗口内执行前向迁移，不执行 EF 降级迁移。
4. 迁移失败时停止切换，保留错误和备份，不修改业务数据绕过模型约束。
5. 回滚应用版本时，数据库必须按兼容策略处理；若版本不兼容，使用完整备份恢复，而不是删除迁移记录。

## 5. 原子切换

推荐目录结构：

```text
/opt/<platform>/releases/<sha>/publish
/opt/<platform>/publish -> /opt/<platform>/releases/<sha>/publish
/opt/<platform>/backups/<timestamp>/
```

切换顺序：

1. 上传并校验新发布物。
2. 停止写入或暂停业务操作。
3. 执行迁移并检查迁移头。
4. 停止主站和需要同步的 Agent 服务。
5. 将软链接原子切换到新 release，保留旧 release。
6. 启动服务，检查服务状态、日志和健康端点。
7. 重新加载网关配置；只有入口 ACK 成功才将动态入口标为可用。
8. 确认新 release 的 `files` 链接仍解析到 `/opt/gzctf/shared/files`，并下载一份已知附件核对状态码、长度和 SHA-256。

## 6. 发布后验收

按影响范围至少检查：

- 首页、登录、本地认证和 Portal SSO；
- 课程、理论、练习、CTF 赛事和后台关键页面；
- PostgreSQL/Redis 连接、迁移头和无异常启动日志；
- 节点 inventory、镜像 Ready/分发状态、部署队列和实例列表；
- 一条可清理的 Docker 实例创建、入口访问、Flag 提交和销毁链路；
- Windows VM、AWDP、TeamLab 只在具备合格测试资产时执行真实验收；
- 公网 Nginx 入口加载、ACK、实际访问和端口回收。

所有验收数据必须可清理，Flag、密码、Token、Cookie、私钥和 Registry 凭据不得写入报告或日志。

## 7. 回滚条件和步骤

出现以下任一情况立即 No-Go：迁移失败、主站无法启动、节点/队列事实异常、入口 ACK 失败、关键业务链路失败、数据备份不可恢复或出现跨队伍/跨实例隔离问题。

回滚步骤：

1. 停止业务写入并保留失败日志和操作时间线。
2. 将软链接切回已验证的旧 release。
3. 恢复与旧 release 匹配的配置和网关状态。
4. 若数据库已经发生不兼容迁移，按备份恢复流程恢复完整数据库和文件存储。
5. 启动服务并重复首页、登录、节点、队列和一条业务链路冒烟。
6. 在 `docs/development/current-state.md` 记录失败原因、回退版本、数据处理和后续任务。

## 8. 禁止事项

- 不在仓库、日志、截图或报告保存服务器密码、IAM Token、Cookie、私钥和完整 user-data。
- 不直接修改生产数据库绕过权限、资源归属、迁移或运行身份校验。
- 不删除唯一旧 release 或唯一备份，未完成冒烟前不清理旧版本。
- 不把“服务进程启动”当作“镜像、节点、实例、公网入口和业务流程全部可用”。
