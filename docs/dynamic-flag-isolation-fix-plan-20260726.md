# 动态 Flag 隔离修复计划

## 目标

- 消除培训和比赛动态容器实例对题目级 `Flags` 集合的污染。
- 动态题详情不再显示配置型多 Flag 步骤，静态多 Flag 行为保持不变。
- 培训实例不再使用固定 `TestTeamHash`，且旧实例重建时数据库、容器环境变量和判题值一致。
- 迁移历史污染数据时保留实例、提交、首次解题和 Flag 记录。
- 查询开销不再随动态题访问用户数持续增长。

## 设计边界

- 不修改比赛战队哈希算法。
- 不改变动态附件 Flag 池及其占用机制。
- 不重新设计静态多 Flag 产品能力。
- 不删除历史实例 Flag 或提交关系。
- 控制器只保留权限与请求编排，Flag 归属和生命周期由模型投影及 Repository 负责。

## 核心测试矩阵

1. 两名学员打开同一培训动态题时得到不同 Flag，各自提交成功，交叉提交失败。
2. 比赛动态容器 Flag 仍由参赛队伍稳定派生，但不进入 `Challenge.Flags`。
3. 动态容器和动态附件详情均不返回 `Flags` 步骤；静态多 Flag 按 `OrderIndex` 返回。
4. 运行或排队环境关联的 Flag 不发生变化；已停止实例重建时可安全替换旧 `TestTeamHash`。
5. 并发创建同一用户、同一题目环境时只执行一次旧 Flag 更新。
6. 迁移仅清空被动态容器实例引用 Flag 的错误题目外键，不处理动态附件池与静态 Flag。
7. 迁移前后的实例 `FlagId`、提交 `FlagId` 和首次解题 `FlagId` 保持不变。
