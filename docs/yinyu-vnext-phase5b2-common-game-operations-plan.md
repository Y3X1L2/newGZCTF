# YINYU vNext Phase 5B-2 比赛通用管理实施计划

更新日期：2026-07-16

## 1. 目标

在不加载旧页面的前提下，为所有比赛赛制补齐共同依赖的管理能力：

- `/admin/games/:gameId/phases`：比赛阶段。
- `/admin/games/:gameId/divisions`：赛区与权限。
- `/admin/games/:gameId/review`：报名审核。
- `/admin/games/:gameId/notices`：比赛公告。
- `GameAdminShell`：类型感知、只展示已实现模块的管理导航。

理论试卷、AWDP 服务和渗透编排继续作为后续独立纵向切片，不在本批套用旧页面或创建空壳入口。

## 2. 契约结论

- 阶段接口实际返回 JSON，但当前 OpenAPI 将响应错误生成成 `Blob`；vNext 必须在适配层进行运行时解析。
- 当前阶段模型只有 `ctfEnabled`，不能伪造 Theory、AWDP 或 Penetration 阶段开关。
- 阶段控制器没有服务端时间重叠和比赛边界校验；前端必须校验，但仍应将后端校验缺口记录为技术债。
- 接受报名会锁定战队并调用实例准备逻辑，审核页面必须在确认前明确影响。
- 赛区权限使用位掩码；页面只通过领域函数读写，不在组件中散落位运算。
- 比赛公告写入后由现有仓储通过 User Hub 推送；前端不重复发送通知。

## 4. 验收原则

- 写测试只使用名称带 `vNext-Phase5B2-Test` 的隐藏测试比赛。
- 报名审核若没有可安全使用的专用报名事实，只做现有数据只读验收，不为测试伪造业务用户。
- 所有写操作必须从对应列表或详情接口回读，不能以 HTTP 200 代替业务成功。
- 后端没有的模块开关、统计或审计时间不由前端推测补齐。
