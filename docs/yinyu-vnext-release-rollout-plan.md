> 最后更新：2026-07-22

## 1. 目标与边界

本计划用于将 YINYU vNext 从本地重构工作区整理为可复现、可验收、可回滚的正式发布版本。由于已有可用维护窗口，后续不再单独搭建完整双实例预发布环境，而是在复用既有自动验收结果的基础上停写、完整备份、直接部署并在开放写入前完成实机验收。

本轮包含：

- 发布候选版本（RC）冻结与审计。
- Docker 全量集成测试。
- IAM 实时身份认证验收。
- Redis、SignalR、OpenTelemetry 和健康检查验收。
- CTF、培训、理论考试、通用管理和 AWDP 业务验收。
- 发布物构建、数据库副本演练、一次性切换和回滚验证。

本轮不包含：

- TeamLab vNext 前端开发。
- 独立练习模块开发。
- 与本次上线无关的界面和功能扩展。

未实现功能必须隐藏、禁用或明确标记，不得伪装为可用功能。

## 11. 回滚条件与步骤

满足以下任一条件立即中止上线：

- 数据库迁移失败或数据核对异常。
- `/healthz` 持续不健康。
- IAM 和本地登录均不可用。
- 节点、队列或容器任务无法收敛。
- 公网实例入口持续不可达。
- Redis/SignalR 出现系统性消息丢失。

开放写流量前回滚：停止新版本、恢复升级前数据库、启动旧镜像和旧配置、验证后恢复服务。

开放写流量后发生严重故障：立即恢复维护模式，先核对新增写入，再决定数据补偿或版本回退，禁止直接覆盖数据库造成数据丢失。
