# YINYU vNext 上线实施计划

> 状态：执行中
> 工作分支：`codex/vnext-clean-rebuild`
> 目标环境：`10.24.0.27`
> 发布策略：离线预发布验证、维护窗口停写、一次性切换、可验证回滚
> 最后更新：2026-07-21

## 1. 目标与边界

本计划用于将 YINYU vNext 从本地重构工作区整理为可复现、可验收、可回滚的正式发布版本。上线前不接入用户流量灰度，不直接在现网调试候选代码。

本轮包含：

- 发布候选版本（RC）冻结与审计。
- Docker 全量集成测试。
- IAM 实时身份认证验收。
- Redis、SignalR、OpenTelemetry 和健康检查验收。
- CTF、培训、理论考试、通用管理和 AWDP 业务验收。
- 发布物构建、数据库副本演练、一次性切换和回滚验证。

本轮不包含：

- TeamLab vNext 前端开发。
- 独立练习模块开发。
- 与本次上线无关的界面和功能扩展。

未实现功能必须隐藏、禁用或明确标记，不得伪装为可用功能。

## 4. 阶段 1：形成可复现 RC

### 4.1 实施步骤

- [x] 审计当前未提交差异，排除密钥、Token、临时文件和无关改动。
- [x] 只读取并记录 `10.24.0.27` 当前发布目录、制品摘要、容器配置摘要和数据库迁移版本。现网制品未嵌入 Git SHA，已用二进制 SHA-256 建立可验证基线。
- [x] 拉取最新 `origin/main`，生成相对当前基线的提交和文件差异报告。
- [x] 确认远端没有本地缺失提交，本轮无需额外 merge 或 rebase。
- [ ] 提交公网入口修复和对应回归测试。
- [ ] 提交验收脚本、验收报告和延期契约清单。
- [ ] 单独提交 NuGet 安全依赖升级。
- [ ] 确认工作区干净并运行快速构建、单元测试和凭据扫描。
- [ ] 创建带说明的 RC 标签，记录父提交和发布范围。

### 4.2 交付物

- 可审查的独立 Git 提交。
- 现网只读基线记录。
- `origin/main` 兼容性报告。
- RC 标签和对应 Git SHA。
- 干净工作区及快速门禁结果。

现网与远端基线见 `docs/yinyu-vnext-production-baseline-20260721.md`。

### 4.3 失败处理

- 发现凭据或临时数据：从提交中移除并轮换暴露凭据。
- 发现来源不明且与当前任务冲突的改动：暂停对应文件，不覆盖原改动。
- 最新 `main` 包含较大功能变更：记录差异并延期，不直接并入 RC。
- 现网基线无法读取：保留阻塞项，不对现网执行任何写操作。

## 5. 阶段 2：实例就绪契约完善

- 后端统一输出 `Starting`、`Ready`、`Failed`、`Stopped` 状态。
- Docker、Windows VM 和培训实例在入口真实可用后进入 `Ready`。
- 前端使用退避轮询，不依赖固定 8 秒等待。
- 查询结果携带入口、剩余时间和可展示的失败原因。
- 比赛实例和培训实例使用同一状态模型和组件。

完成门禁：启动速度变化时不会提前展示入口，失败状态可恢复且可追踪。

## 6. 阶段 3：Docker 全量集成测试

- 记录测试前容器、网络和卷，不删除非测试资源。
- 执行 `GZCTF.Integration.Test` 全部 236 项。
- 按代码失败、环境失败和主动跳过分类记录。
- 修复后必须完整重跑。
- 核对测试容器、网络、卷和端口残留。

完成门禁：236 项通过，或只有经过书面批准的环境跳过项，且无资源泄漏。

## 7. 阶段 4：IAM 实时验收

- 使用浏览器取得短期有效门户 Token，不写入命令历史和文档。
- 验证新 IAM 用户自动创建、相同 IAM ID 重复登录不重复创建。
- 验证既有绑定、`data.user` 嵌套结构、姓名和角色同步。
- 验证过期或伪造 Token 返回 `401`，无权限返回 `403`。
- 验证 `returnUrl` 只允许站内路径。
- 验证 IAM 故障时本地登录仍可使用。

完成门禁：身份唯一性、权限映射、异常路径和本地登录全部通过。

## 8. 阶段 5：基础设施与实时能力验收

- 启动两个候选后端实例并连接同一 Redis 和测试数据库副本。
- 跨实例验证 SignalR 通知、排行榜、队列和 AWDP 状态更新。
- 验证 `/healthz` 中 Database、Redis 和 Storage 状态。
- 验证 OpenTelemetry 指标、日志和链路可导出。
- 检查遥测数据不包含 Flag、密码、Token 和 Cookie。

完成门禁：跨实例实时消息正常，依赖异常能够被健康检查识别。

## 9. 阶段 6：完整业务验收

自动和浏览器验收范围：

- IAM 与本地登录。
- CTF 静态 Flag、动态 Flag、附件、Docker 和 Windows VM。
- 理论考试、培训报名、理论作业和课程实例。
- 用户、战队、学员组和系统设置写操作。
- 节点注册、镜像拉取、任务队列和公网入口。

AWDP 按 `docs/yinyu-awdp-manual-acceptance.md` 由测试人员手工验收，回填双队实例、攻击、修补、重置、恢复、停止和资源清理证据。

## 10. 阶段 7：发布物与离线演练

- 从最终 RC SHA 构建前端和后端。
- 镜像使用 Git SHA 标签，不仅使用 `latest`。
- 生成数据库 migration bundle 和 SHA-256 清单。
- 备份现网 Compose、环境变量、Nginx、WireGuard、FRP 和公网入口配置。
- 使用生产数据库副本完成最终恢复、迁移、启动和回滚演练。

完成门禁：任何成员均可从固定 SHA 重建相同发布物，并按文档完成恢复。

## 11. 阶段 8：维护窗口一次性上线

1. 开启维护模式并停止外部写入。
2. 执行最终数据库备份并校验摘要。
3. 停止旧应用，保留旧镜像、Compose 和配置。
4. 执行 migration bundle。
5. 启动固定 SHA 的候选版本。
6. 从内网验证 `/healthz`。
7. 验证登录、比赛、培训、节点、镜像、队列和实例入口。
8. 检查公网 Nginx、WireGuard/FRP 入口。
9. 全部通过后关闭维护模式并一次性开放流量。

## 12. 回滚条件与步骤

满足以下任一条件立即中止上线：

- 数据库迁移失败或数据核对异常。
- `/healthz` 持续不健康。
- IAM 和本地登录均不可用。
- 节点、队列或容器任务无法收敛。
- 公网实例入口持续不可达。
- Redis/SignalR 出现系统性消息丢失。

开放写流量前回滚：停止新版本、恢复升级前数据库、启动旧镜像和旧配置、验证后恢复服务。

开放写流量后发生严重故障：立即恢复维护模式，先核对新增写入，再决定数据补偿或版本回退，禁止直接覆盖数据库造成数据丢失。
