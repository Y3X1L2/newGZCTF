# YINYU vNext 代码基线审计与治理记录

更新日期：2026-07-16

## 1. 审计结论

本轮审计和治理聚焦前端分层、路由组件职责、运行时入口安全和可重复门禁，不新增产品功能。

治理后基线满足以下条件：

- vNext 不依赖 Mantine、旧页面组件、`yy-*` class、旧全局视觉样式或内联样式。
- vNext TSX 不再默认导入生成的 `@Api` 客户端。
- 页面请求遵循 `Page -> Controller/Hook -> Feature Adapter -> Generated Client`。
- 战队、课程章节和账户设置三个高耦合路由已经按领域拆分。
- strict TypeScript、lint、架构检查、自动化测试和生产构建作为统一退出门禁。

## 2. 本轮已修复问题

### 2.1 生成 API 依赖扩散

修复前有 26 个 TSX 直接 `import api from '@Api'`，请求、缓存、表单和视觉状态混在页面中。

修复后：

- 首页、公告、账户、战队、比赛选手端、理论考试和培训模块均通过功能域 Adapter。
- 比赛实例、Flag 提交、培训实例和培训 Flag 提交也通过对应 Adapter。
- 架构脚本会拒绝 vNext TSX 新增默认 `@Api` 导入。

### 2.2 超大路由组件

| 路由文件                  | 修复前 | 修复后 | 处理方式                                              |
| ------------------------- | -----: | -----: | ----------------------------------------------------- |
| `TeamsPage.tsx`           | 641 行 | 223 行 | 提取 Controller、概览、成员、申请和设置面板           |
| `TrainingChapterPage.tsx` | 624 行 | 144 行 | 提取章节 Controller、视频、实验、理论、完成条件和导航 |
| `SettingsPage.tsx`        | 588 行 |  55 行 | 分离资料、安全和 API Token 工作区                     |

状态和写操作没有复制到展示组件；Controller 仍是唯一编排入口。

### 2.3 实例入口不一致

旧接口可能返回裸 `host:port`，导致管理页和选手页不能直接打开。

修复后：

- Adapter 将裸入口规范化为 HTTP URL。
- 只允许 HTTP/HTTPS，拒绝 `javascript:`、`data:`、`file:` 和带凭据 URL。
- 不安全入口仍可作为诊断文本显示，但不渲染可执行链接。

### 2.4 首页活跃度日期错位

修复前使用 `toISOString()` 生成日期键，UTC+8 本地午夜会落到前一天。

修复后使用本地年、月、日生成 `YYYY-MM-DD`，并有时区回归测试。

### 2.5 过时待建设说明

待建设页已按当前 vNext 实际能力更新，不再声称只完成首页和赛事列表。

## 3. 架构门禁

`pnpm build` 依次执行：

1. 多语言资源校验。
2. vNext lint。
3. strict TypeScript。
4. 前端架构检查。
5. 自动化测试。
6. Vite 生产构建。
7. 产物清单和 bundle 预算检查。

新增逐文件预算：

- `TeamsPage.tsx`：260 行。
- `TrainingChapterPage.tsx`：180 行。
- `SettingsPage.tsx`：80 行。
- 对应 Controller 与领域面板也设置独立预算。

CSS Module 不按纯行数机械拆分。组件职责拆分时同步迁移样式，禁止重新形成跨页覆盖链。

## 4. 自动化覆盖

本轮新增或扩展覆盖：

- HTTP/HTTPS 资源白名单与危险 scheme 拒绝。
- 裸实例入口规范化和不安全入口不渲染链接。
- 本地日期键与 UTC+8 回归。
- 战队路由参数和 Tab 白名单。
- 章节层级、必做实验、理论及格线和历史完成状态。
- 管理实例旧接口入口规范化。

副作用流程和尚缺后端契约的内容单独记录在 `docs/yinyu-vnext-deferred-contract-gaps.md`，不使用前端伪数据掩盖。

## 5. 后续约束

- 新模块先建立 Adapter 和领域模型，再实现路由页面。
- 路由页面只负责参数、权限、Controller 和区域组合。
- SWR key、写操作、缓存失效和兼容响应不得散落在 JSX。
- 新功能必须补充领域测试；高风险写操作还需要浏览器业务回归。
- 达到行数上限不是唯一拆分依据，职责混合应在达到上限前处理。
