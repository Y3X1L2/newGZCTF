# YINYU vNext Phase 5B-3 理论考试管理实施计划

更新日期：2026-07-16

## 1. 目标

在不加载旧 Mantine 页面、不伪造后端能力的前提下，补齐理论考试管理闭环：

- `/admin/theory-bank`：全平台共享理论题库。
- `/admin/games/:gameId/theory-paper`：一场比赛一套理论试卷，支持指定题目和随机抽题。
- `/admin/games/:gameId/theory-results`：队伍榜单、个人答卷摘要和成绩重算。
- `GameAdminShell`：Theory 和 Mixed 比赛显示理论试卷与理论成绩入口。
- 复用现有 vNext `TheoryExamWorkbench`，完成管理员组卷到选手提交和成绩回读的端到端验收。

## 2. 已确认接口

### 2.1 全局题库

- `GET /api/admin/theory/questions?keyword&count&skip`
- `POST /api/admin/theory/questions`
- `PUT /api/admin/theory/questions/{id}`
- `DELETE /api/admin/theory/questions/{id}`

题目模型保存题型、题库名称、题干、说明、选项、正确答案索引和标签。支持单选、多选、判断；多选完全一致才得分。

### 2.2 比赛试卷

- `GET /api/admin/theory/games/{gameId}/paper`
- `PUT /api/admin/theory/games/{gameId}/paper`
- `POST /api/admin/theory/games/{gameId}/paper/publish`

后端保证一场比赛一套试卷。试卷问题保存题目快照、来源题目 ID、分值和顺序；保存会回到未发布状态，已有已提交答卷时拒绝编辑。

### 2.3 理论成绩

- `GET /api/admin/theory/games/{gameId}/results`
- `POST /api/admin/theory/games/{gameId}/results/recalculate`

返回个人答卷摘要和队伍榜单；队伍成绩采用成员最高分。

## 3. 接口缺口与处理决策

### 3.1 JSON 批量导入没有服务端事务

当前没有 bulk、dry-run 或回滚接口。

本阶段替代方案：

- 浏览器本地严格解析全部 JSON，任何格式错误都会阻止写入。
- 导入前展示新增、覆盖、跳过和错误数量及前 20 条预览。
- 重复判定使用“题库名称 + 题型 + 规范化题干”。
- 明确提供跳过、覆盖、新增副本三种策略。
- 写入采用有界串行请求，显示实际完成数；失败后停止并保留已成功记录，不宣称原子事务。
- 导入结束后从服务器重新读取题库，以服务器事实生成结果。

后续退出条件：新增批量预检与事务导入接口后，替换逐题写入实现。

### 3.2 服务端筛选和总数不足

生成客户端只有 `keyword/count/skip`，没有题型、题库、标签和总数契约。

本阶段替代方案：读取最多 5000 条，在客户端进行题型、题库和标签筛选，并明确显示“当前加载数据”。不实现虚假的服务端总数和无限分页。

后续退出条件：接口返回 `data/total` 并支持 `type/bank/tag` 查询后切换为服务端筛选。

### 3.3 缺少逐题答卷详情

`TheoryResultsModel` 只有答卷摘要，没有每道题的选择、正确答案和对错结果。

本阶段暂缓：成绩页只展示后端真实返回的队伍榜单和个人答卷摘要，不创建空详情抽屉。

建议新增：`GET /api/admin/theory/games/{gameId}/results/{sheetId}`，返回答卷快照、提交答案、正确答案、单题得分和判分结果。

### 3.4 缺少成绩导出接口

本阶段不显示导出按钮。后续新增服务器导出接口后再实现 CSV/XLSX 下载。

### 3.5 当前稳定服务器未持久化理论题目标签

2026-07-16 在 `10.24.0.27:8080` 真实创建题目 `#93` 时，前端提交了 `vNext`、`Phase5B3`、`CRUD` 三个标签，但创建后和再次编辑后的服务器回读均为 `tags: []`。

仓库当前 `TheoryAdminController`、`TheoryQuestionEditModel` 与 `EfTheoryQuestionCatalog.SetTagsAsync` 已包含标签写入和查询实现，因此该现象按“稳定服务器后端版本尚未同步标签持久化实现或迁移”记录，不在前端伪造本地标签。

本阶段处理方式：

- 题库页面继续展示服务器真实返回的标签；服务器返回空数组时明确显示“无标签”。
- 标签筛选只作用于服务器本次真实返回的数据，不从本地提交状态补全。
- 试卷组卷不依赖标签作为唯一选择条件，仍可使用题库名称、题型和题目指定选择。
- 在部署当前仓库后端和数据库迁移后，必须重新执行标签创建、编辑、筛选和删除回读验收，才可关闭该差异记录。

### 3.6 理论管理页面使用舒适密度，不复用运维表格密度

理论题库、组卷和成绩页面属于需要持续阅读题干、说明和成绩语义的业务工作台，不能直接采用节点、队列和日志页面的紧凑密度。

本阶段布局约束：

- 三页统一使用 `var(--yn-page-max-width)`、`var(--yn-page-gutter)` 和标准页面上下留白，不让内容贴住管理壳边缘。
- 题库遵循“左侧题型/题库/标签筛选，右侧搜索与主表”的设计文档，不把全部筛选压在单行工具栏。
- 组卷遵循“左侧共享题库，右侧试卷结构”的设计文档；宽屏题库列限制在 340-400px，剩余空间优先给试卷题目和分值编辑。
- `AdminWorkbench` 增加显式 `compact/comfortable` 密度契约。理论业务页使用舒适密度；运维页面默认值不变，避免通过全局字号覆盖引入回归。
- 低于断点后按完整区段重排，不继续压缩业务文字；移动端只允许表格容器内部降列，不允许页面级横向滚动。

### 3.7 当前稳定服务器试卷快照未回传题库名称

测试比赛 `#98` 保存后，试卷问题的题型、题干、选项、答案、来源题目 ID、分值和顺序均正常回读，但 `bankName` 未从当前稳定后端回传，直接渲染会被错误展示为 `Default`。

本阶段替代方案：

- 组卷页只在显示层按 `sourceQuestionId` 查询本次服务器回读的共享题库，补充题库名称。
- 试卷保存 payload、已选题目快照和共享题库对象仍保持独立，不把显示补全写回成服务器事实。
- 如果来源题目已删除或当前账户无权读取，则如实回退为 `Default`，不缓存旧题库名称。
- 后续后端在试卷详情模型中正式返回题库名称后，删除该显示补全分支并以试卷快照为准。

## 5. 验收原则

- 写测试只使用名称带 `vNext-Phase5B3-Test` 的隐藏理论比赛和题库。
- 所有写操作必须从题库、试卷、选手答卷和成绩接口回读。
- JSON 导入部分成功时必须报告成功和失败范围，不使用笼统“导入成功”。
- 不修改现有比赛试卷、答卷和共享题库数据。
- 不从旧页面复制 DOM、CSS 或 Mantine 组件；仅复用生成类型、业务契约和已确认的纯领域逻辑。
