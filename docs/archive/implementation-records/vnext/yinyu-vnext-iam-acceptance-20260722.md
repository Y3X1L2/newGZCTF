## 1. 验收目标

验证统一身份认证在候选版本上的真实端到端行为：

- 门户 Profile 响应的 `data.user` 嵌套结构能够解析。
- 首次登录自动创建本地用户和稳定外部身份绑定。
- 相同 IAM ID 重复登录不会重复创建用户或绑定。
- IAM 角色正确映射到平台角色。
- 伪造、过期、无权限和故障路径按契约失败。
- `returnUrl` 不允许跳转到站外地址或使用反斜杠混淆。
- IAM 故障不影响本地密码登录回退。

## 4. 数据库证据

首次登录后的测试库状态：

- `AspNetUsers`：2 条，包括本地 `Admin` 和自动创建的 `iam_12`。
- `AspNetUserLogins`：1 条 `PortalIAM` 绑定，`ProviderKey=12`。
- `iam_12`：1 条，`RealName=超级管理员`，角色值对应 `SuperAdmin`，邮箱已确认。

使用同一 IAM Token 再次登录后，上述计数不变。无平台权限响应器返回合法用户但空平台清单时，平台返回 `403`，数据库中未出现该用户。

## 5. 验收中发现并修复的问题

原 `returnUrl` 校验只拒绝以 `/\\` 开头的路径，`/training\\evil` 会进入 IAM Token 校验阶段。虽然当前控制器使用 `LocalRedirect` 形成第二道保护，但预校验契约不完整。

修复后规则拒绝任何包含反斜杠的 `returnUrl`，并新增以下集成测试：

- `https://evil.example`
- `//evil.example`
- `/\\evil`
- `/training\\evil`

定向认证集成测试结果为 `22/22` 通过。

## 6. 故障回退验证

候选应用临时改用不可达 Profile 地址并独立重启：

- SSO 请求返回 `504`，未建立新会话。
- 本地 `Admin` 密码登录返回 `200`。
- IAM 故障不会把本地管理员一并锁在系统外。

随后使用本地临时 IAM 响应器返回无 CTF 平台权限的合法 Profile，服务返回 `403` 且未创建用户。临时响应器不连接真实 IAM，也不保留任何身份数据。

## 7. 最终结论

IAM 阶段完成门禁。真实登录、身份唯一性、角色映射、嵌套响应兼容、异常令牌、授权拒绝、重定向边界和本地登录回退均符合预期。

本记录不代表允许直接部署生产。后续仍需依次完成基础设施与实时能力验收、完整业务验收、固定 SHA 发布物和离线回滚演练。
