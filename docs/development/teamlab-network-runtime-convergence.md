# TeamLab 网络与运行链收敛

基线：`bc3599a`。本文件记录本轮实施和验证，不把静态推断写作现场结论。

## 实施顺序

1. 统一 V2 网络意图：分片能力按实际资产计算；自动网络模式复用固定租约下发地址、网关和 DNS，Windows 不再挂无效的 Linux NoCloud 网络盘。网段可选一次 DNS 资产，运行时使用该环境的资产地址；普通网段无需配置。
2. 收敛热更新：OVN 只改变化的网络对象；现场资源按运行实例与代次归属，不以计划摘要归属。当前计划保存已提交事实，现有操作票据保存进行中的目标，失败和中断不得宣称已回滚。
3. 清理旧执行入口：确认生产调用后移除不用的单资产创建、等待、探测、旧分片清理方法和路由应用入口，保留 V2 实际使用的计划编译能力。
4. 定向验证：混合能力节点、Windows/Linux/Docker 网络、单/双网卡、热更新中断与回滚、完整销毁和资源残留。自审通过后按生产发布规范部署 `.27`，再核对真实执行面。

## 边界

- 不加入 AD、Netlogon 或比赛规则专用逻辑；AD 仅作真实场景验收。
- 不新增队列、资源表、全量对账服务或持续健康探测。服务健康是观测，不阻断资源创建。
- 已存在的计划 JSON 是在运行环境的清理依据。契约变更必须让这些计划继续可读，不恢复旧执行路径。

## 本轮进度（2026-09-27）

- 已完成网段可选 DNS 资产的场景、发布、计划和界面贯通。未选择时沿用平台默认地址；选择后使用运行实例中该资产的分配地址。
- Windows VM 不挂 Linux NoCloud 网络盘；使用 DHCP 的 VM 由 OVN 下发地址与 DNS。Linux VM 的 NoCloud 只配置有平台 DHCP 租约的接口。
