## 集成范围

1. 保留已部署验证的来宾网络链路：VM 网络模式、逐网卡名称/IP/DNS/默认网关/静态路由、Linux cloud-init/Netplan、Windows QGA 应用与回读、声明 MAC 就绪等待及原错误语义。
2. 保留管理员重设计的场景库、发布版本、运行环境、资产、网络与流量、活动记录、资源登记、文件与远程访问工作区。
3. 对照当前后端契约核对镜像登记、场景草稿、发布版本、运行环境、资产编排、远程访问和生命周期请求；生成 API 仅通过项目生成流程更新。
4. 保持 `Dhcp=0`、`Preconfigured=1` 和存量 release/plan 读取兼容。主网卡、DNS 归属和默认路由保持独立语义；界面不得自动创建跨网段路由。
5. 更新当前状态与任务交接，只记录本分支实际完成的合并和验证；不更改生产服务器、数据库、网关或保留的四机运行环境。

## 主要风险

- 两条分支同时修改 TeamLab 前端 adapter、拓扑模型、检查器、运行环境工作区和生成 API，冲突解决可能误删受管网络字段或重设计交互。
- 两条分支均包含迁移和模型快照；必须同时保留受管网络迁移与对象日志索引迁移，并验证 EF 模型一致性和前向升级。
- 管理后台替换资产会回读并复用现有执行定义；集成后必须确认逐网卡受管网络要求完整往返，不按界面默认值重建网卡。
- 远程访问、生命周期和文件操作是异步或真实执行能力；前端不得把受理状态显示为执行成功，自动化通过也不等于真实基础设施复验。
