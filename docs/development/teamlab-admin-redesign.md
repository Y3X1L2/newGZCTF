## 页面组织

| 区域 | 当前实现 |
| --- | --- |
| 工作台 | 左侧单一组网入口，内部使用场景、运行环境、资源导航 |
| 场景库 | 名称、发布状态、网段与资产数量、最近运行状态；删除当前页统计条 |
| 发布版本 | 左侧版本列表，右侧创建条件、镜像准备和最近试运行 |
| 运行环境 | 概览、资产、网络与流量、活动记录四个视图 |
| 资产 | 左侧可搜索资产列表，右侧所选资产的连接、服务、文件和诊断 |
| 资产编排 | 抽屉新增、替换、移除；集中提交本轮变更 |
| 文件 | 目录树、文件表格、选中项工具栏、双击、右键与键盘操作 |
| 网络与流量 | 网段连接视图、真实通信记录 Sankey 图、点击详情、统一筛选及抓包抽屉 |
| 活动记录 | 操作、事件、诊断日志切换；详情按需打开，不再上下重复展示 |
| 资源 | 设备模板、现场连接器；节点缓存放入运维详情 |

主界面移除 SHA-256、原始 Schema、部署票据和分片指标。诊断所需运行编号和票据保留在部署详情。错误及恢复操作仍直接展示。资产操作和远程连接不再要求填写原因。

删除旧 `ReleasePlanPanel`、`RuntimeTopologyView` 和被替代的样式；复用现有 adapter、执行链、主题和基础组件。菜单使用共用 `ActionMenu`，未引入第二套 UI Provider。

## 链路修复

- 公共端口续期加入有效 TeamLab 服务映射，复用原租约及分配器；移除仅在外部 Nginx 模式运行的限制。
- 替换资产通过 `GET /api/admin/teamlab/runtimes/{runtimeId}/assets/{assetId}/definition` 读取当前资产执行定义，要求 `AssetCompose`。沿用现有网卡键、地址序号、顺序、服务配置和资源规格；替换界面不重新分配网卡地址。定义读取失败时显示真实错误，不能用推测配置提交。
- 资源登记表单先读取事件值，再更新状态，修复延迟读取 `currentTarget` 的空引用。
- 内部 API 客户端由当前契约重新生成。原生成文件落后于运行资产更新、授权和执行模型收敛源码，生成差异包含这些既有契约。

## 对象日志故障

2026-10-01 连接 `.27` 后只读核查历史异常与查询计划：

- `LogRepository.GetLogs` 在读取 PostgreSQL 结果时超时，主站返回 500。
- 日志表有时间、级别、关联号、事件和节点索引，没有资源类型及资源编号索引。
- 资源日志查询采用分区并行顺序扫描。两个有数据分区的估计行数合计约 3,580 万。
- 新增前向迁移 `20260930164900_AddSystemLogResourceIndex`：资源类型、资源编号、时间倒序及记录号倒序复合索引，仅收录资源字段非空的日志。查询和返回模型保持不变。
- PostgreSQL 16 临时分区表验证索引创建、查询和删除；查询使用资源索引，删除后 20,000 条测试记录保留完整，事务回滚。未修改生产日志表或迁移历史。临时表执行耗时不作为生产性能数据。

该索引的正式迁移需要发布时安排执行：普通索引构建会锁住涉及表的写入，本轮没有在生产执行。生产对象日志恢复结果尚未验证。
