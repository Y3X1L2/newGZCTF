# 镜像引用与节点缓存回收候选

## 任务目标与基线

- 用户要求按需分发、减少主站存储压力，并建立明确的资源回收机制。本分支只负责镜像引用、销毁尾部和安全回收查询；按需分发调用方与 Agent 下载容量由并行分支负责。
- 起点：`origin/main 2ba6e8d8`；任务分支 `codex/image-cache-reclamation`；工作树 `C:/Users/Cloud/.codex/worktrees/image-cache-reclamation/newGZCTF`。
- 未连接或修改生产服务器、Registry、PVE 源机、快照、旧模板、备份和公网入口。本候选不代表已经部署或完成真实双环境验收。

## 当前删除流程（源码核对）

镜像文件有三种不同的用途，删除其中一种不等于删除另外两种：

| 内容 | 保存在哪里 | 正常回收条件 |
| --- | --- | --- |
| 可重建的正式制品 | 独立 Registry；部分旧导入仍只有或另有 `LocalFilePath` | 模板没有业务引用，再通过 Content 的全局模板删除 |
| 节点缓存底盘 | Worker 的 VM 镜像目录或 Docker 引擎 | 没有节点需求，且 Agent 确认没有实际使用者 |
| 每个实例自己的写入内容 | TeamLab 运行目录中的 qcow2 overlay、Docker 容器等 | 对该实例正常销毁，保留其他实例和缓存 |

1. 全局模板删除首先检查所有权和 CTF、Exercise、Training、TeamLab 公开引用查询。TeamLab 草稿和不可变版本仍保护正式制品；不能因没有运行实例就删除其唯一来源。
2. Content 在事务中将模板标记为 `Deleting`。执行节点缓存清理后，删除 Registry manifest，再删除可选本地 VM 源文件及模板元数据。清理失败保留 `Deleting` 和错误，后台每分钟重试。
3. 节点缓存清理锁定该模板与节点，重新读取需求。VM 还检查主站的所有非 `Destroyed` VM，Agent 再检查实际 qcow2 backing chain。停止和报错的 VM 依然需要底盘；不能只检查正在运行的进程。
4. Agent 的下载与底盘删除使用同一 `BaseImageLockKey`。共享下载的一个调用者取消不表示写入者结束，不能直接删 `.part`。主站遇到仍有效的下载 claim 时暂不转为清理；写入者结束后，既有定期对账会安排回收。
5. 实例销毁与撤销预热不会删除 Registry 的正式制品。后续新建由所选节点按需准备。

## 已实现的候选改动

- 普通排队销毁原来走 `CleanupAsync(false)`，释放 runtime 引用后调用没有回调的静态终态方法，遗漏最后消费者的 release preparation 释放。本候选统一调用 `FinalizeDestroyedAsync`。
- 终态先持久化，再按销毁时点撤销较早的版本预热。重复销毁重试这段尾部，并保持原终态时间。管理员在销毁后重新预热，或在候选查询后、加锁前续约的引用，不会被旧销毁误删。
- generation 物理清理也用于 reset。它继续按既有流程标记前一代 `Destroyed`，但不撤销预热；正在处理的统一队列 Reset ticket 继续被视为消费者。
- 既有五分钟引用对账可恢复明确漏接的旧销毁尾部：同一 release 的消费者全部 `Destroyed`、都有可靠终态时间、没有活动 Reset ticket，只撤销终态时点之前的预热。没有 runtime 的明确预热保留；历史终态时间缺失时保守保留。
- runtime 节点需求按当前 generation、未销毁资产及实际 Worker 匹配。Reset 临界期保留此前需求；下一代完成后，只清理不再需要的旧节点引用。
- 批量模板预热没有对应业务实体，原来被 switch 的默认分支立即认成失效。本候选明确保留该管理员需求，后续应补预热租约与取消契约。
- TeamLab 全局删除引用查询补上运行资产，保护没有进入草稿或冻结版本的热添加资产，包括停止、报错、暂停和正在重置的环境。这保护的是正式制品，不让每个历史版本永久固定所有 Worker 缓存。

没有数据库迁移、外部 API DTO、生成代码、前端或 Agent 改动；只新增内部按时间截止释放方法。原 `ReleaseAsync` 仍用于明确管理员取消。

## 明显缺口与后续策略

1. **Registry blob 空间回收尚未接通。** 删除 manifest 只撤销文件目录，不立即回收共享 blob。后续单独实施受控 GC：从数据库、Registry inventory 和正在上传的制品核对引用，暂停写入或启用只读，先预览，再执行并复核所有保留制品可拉取。不得在线盲扫 Registry 目录，不能把模板删除成功称为磁盘空间已释放。
2. **管理员预热缺少 owner、租约和空间预算。** release 预热已有撤销入口；批量模板预热尚无对应的撤销 API。本候选保守保留明确需求，没有新增默认 TTL，也不自动批量删除历史需求。下一阶段将两者统一为指定节点、有截止时间、可取消的租约，而不是将历史 release 当成所有节点的永久缓存需求。
3. **课程等缓存需求仍存在较粗的业务粒度。** 本期修 TeamLab 当前实例与节点的对应关系；不能宣称所有模块都已有逐实例缓存租约。新分发与分盘容量修正应先实测，再收紧旧需求。
4. **本地 VM 导入暂存仍需收口。** 正式制品在独立 Registry 校验可用后，主站可以释放自己的重复上传文件；旧 `LocalFilePath` 可能是唯一来源，必须先登记来源、大小与摘要并确认迁移。不能按路径年龄直接删。当前候选未改这条导入生命周期。
5. **正式制品不要求永久保留，但必须能重建。** 建议保留被场景/版本/运行引用的制品；通过明确退休版本和模板删除撤销最后引用，设置宽限，再受控 GC。主站不必长期保存重复字节。节点缓存可以随需求撤销；唯一正式制品不能随最后一个实例销毁。
6. **claim 与实际共享写入者并不等价。** Agent 文件锁保留最终保护，但无节点 orphan `.part` 的超时 GC。本候选没有改变 shared transfer 取消行为，不在主站按 HTTP 调用者消失归还或删除写入空间。
