4. 执行前后端回归及必要集成验证，记录结果、提交并推送。

## 已定位证据

- vNext 多个入口直接调用 `navigator.clipboard.writeText`，没有 HTTP 环境回退。已有旧 `copyText` 回退未被这些入口使用。
- Course GET 构造章节列表时未查询或传入当前用户的 TrainingChapterProgress，前端将空状态显示为未开始。
- Course GET 的课程题目映射未附带章节 ID，章节列表也未附带题目关联，管理页面直接据空 chapterId 显示未绑定。
- 在用户登录的内置浏览器复现：章节 69 显示 6/6 实验及章节已完成，课程列表却显示 0/1 和未开始；1366 宽度下六题全部显示未绑定章节。点击复制出现 `Cannot read properties of undefined (reading 'writeText')`，部署静态文件标识为 `20260910T07202`。
- RecalculateProgress 在章节状态尚未保存时只查询数据库，漏计本次完成；首次完成时两次 EnsureChapterProgress 还可能重复创建同一主键的跟踪实体。

## 修复内容

- 新增不依赖 Mantine 的复制工具和 hook，优先使用 Clipboard API，HTTP 或权限拒绝时尝试 DOM copy；失败返回真实结果。临时节点位于当前原生 dialog 内，复制后清理并恢复焦点/选区。
- vNext 实例入口、远程连接字段、邀请码、公钥、Token、密码结果共用该实现，并显示成功或失败状态；保留旧页面也统一底层复制实现，旧 Shared.copyText 改为转导出。
- TrainingCourseDetailProjectionService 在已有授权检查后按当前用户、课程和可见章节批量查询进度、判题与绑定。课程详情和管理详情复用该投影；未报名用户不获得章节/题目明细，学员看不到草稿章节绑定。
- 课程详情用实际章节进度计算完成数量，已有过期课程聚合值不会使详情继续显示 0%。章节集合保留一个题目绑定多章的事实，界面显示全部绑定；旧 chapterId 仅在单一绑定时填充。
- 课程完成计算合并尚未保存的章节状态，与课程进度一起保存；EnsureChapterProgress 优先使用当前 context 的已跟踪实体，支持首次完成和重复确认。
- API 字段结构、数据库模型和迁移没有变化，无需重新生成客户端或迁移数据库。
