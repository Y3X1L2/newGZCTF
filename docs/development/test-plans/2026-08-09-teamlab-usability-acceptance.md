## 已修复：运行状态与观测前置问题

| 项目 | 结果 | 证据 |
| --- | --- | --- |
| 流量与路径筛选切换 | 已修复 | 原先 SWR 在筛选或分页键变化时保留旧页数据，界面可能短暂把旧结果显示为新条件结果。现改为新请求期间明确显示加载态，不复用不同查询键的数据。 |
| 编辑器保存合同 | 环境阻断，待统一部署 | 真实页面修改独立草稿后，118 返回 `The model field is required.`。本地前端发送当前源码定义的直接拓扑更新模型，而 118 仍是旧写入合同；不能在前端增加双轨请求掩盖版本漂移。 |
| 容器终端强制结束 | 代码与定向测试通过，待真实 Agent 验收 | 主站的关闭、过期、暂停和销毁沿用既有 `DELETE` 节点网关；Agent 新增可取消终端登记。关闭请求会取消运行中的 `docker exec`，并阻止控制面已经结束后的延迟 WebSocket 重新接入。 |
| 远程会话节点容量 | 代码与定向测试通过，待真实并发验收 | 节点顾问锁与 100 会话上限不再排除容器终端，SSH、RDP 与容器终端共享同一节点容量事实。 |

后续真实运行验收必须先部署可追溯的统一前后端版本；当前工作区含多位协作者的未提交改动，不能直接作为发布物。

本轮定向验证：`TeamLabTerminalSessionRegistryTests` 2/2 通过；主站与 Agent 的 Release 构建均为 0 警告/0 错误；`pnpm check` 通过；画布、检查器、运行时和自动布局前端测试 19/19 通过；`git diff --check` 通过。现有测试项目的历史 xUnit 警告未在本轮扩大修改。

全解决方案构建未作为本轮门禁：本机 `GZCTF.AppHost` 缺失已还原 NuGet 分析器（Aspire/MessagePack 等），报错均为外部包元数据文件缺失，受影响的主站、Agent 和前端项目已分别通过构建。

## 已确认但待部署验证

- 服务目录详情契约已补 `updatedAt`，前后端约定为现有 vNext 时间数字格式；当前 118 仍运行旧后端，详情响应缺该字段，会触发旧前端错误。必须部署本次后端后以真实服务目录重新验收。
- Docker 资产不提供服务注入执行器。编辑器禁止新启用，发布校验返回中文明确错误；VM 服务注入仍需做真实执行验收。
