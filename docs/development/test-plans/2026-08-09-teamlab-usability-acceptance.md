## 2026-08-09 低负载 v4 试运行根因与待复验

- 已由管理端真实操作创建 v4 试运行 `019fe50c-2503-794b-9490-61a82274aa82`。运行时完成镜像准备、分片调度、网络、路由和基础设施创建后，在 Docker 资产创建阶段进入失败并完成清理；没有留下运行中资产。
- 运行页给出的真实失败原因是 `docker:create: Invalid ContainerInterfaceName.`。根因是执行器将拓扑接口键直接作为容器内 Linux 网卡名，而接口键允许业务可读的 63 字符标识，Linux 设备名上限为 15 字符。
- 已在候选代码中将逻辑接口键与来宾设备名分离：Docker 挂载、容器网络收尾和 VM cloud-init 统一使用按接口顺序生成的 `eth0` 至 `eth7`；拓扑键仍只用于业务编排、审计和宿主侧稳定命名。主站与 Agent Release 构建通过。
- 该运行时作为失败清理证据保留，不重置复用。必须部署统一主站与 Agent 候选后，以新运行时重新执行 v4 试运行，再继续服务注入、运维、流量和生命周期验收。
