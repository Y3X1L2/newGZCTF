日期：2026-10-01；更新：2026-10-02。状态：实现与本地全量门禁完成，发布准备中，待部署批准。用户授权开发、分配子代理、最后在服务器部署测试；**部署前必须再次询问用户**。开发阶段允许本地代码、测试、文档和发布物准备；未获部署批准前不改变服务器版本、生产数据库、Agent或现有实例。

## 问题与目标

当前平台能够创建网卡和外部网络，DHCP镜像已通过真实实例验证。但PVE静态镜像迁移后，Linux接口名字变化、Windows新设备不继承旧配置；Preconfigured模式不自动应用来宾网络，导致人工修复。

本轮让场景声明的网络要求自动对应到本次网卡，再回读真实结果。镜像只需准备兼容驱动、Linux初始化工具和必要QGA管理通道；每道题不再另写网卡修复脚本。AD和题目业务启动仍独立处理。

## 本轮交付范围

1. **明确两种新建方式。** 新建场景以DHCP自动取址与平台静态配置为主。只保留Dhcp=0、Preconfigured=1的已有数值和旧计划读取，避免重解释存量数据；旧预配置值在界面作为迁移状态，不新增复杂兼容修补系统。场景资产未选模式时继承模板，新发布冻结最终模式。
2. **逐接口网络要求。** 接口按稳定key与本次MAC对应；支持目标接口名、是否使用默认网关、DNS继承/明确列表/明确无DNS、有限静态路由。空值与“明确不设置”不同；多卡不按猜测顺序写配置。配置字段须贯通保存、发布、计划、重置、运行更新和校验。
3. **Linux自动应用。** 复用NoCloud配置盘和cloud-init/Netplan，以当前MAC匹配接口，正确处理新建/重置实例标识；平台管理静态模式生成网络配置，预配置模式不生成。镜像须支持对应工具，不能把文件生成成功当成来宾已应用。
4. **Windows自动应用。** 在TeamLab执行链接入身份限定的QGA网络配置与回读。复用现有VM管理基础；提供兼容现代Windows及Server2008R2的执行方式，不依赖旧系统缺少的Get-NetAdapter等命令。网络尚未通时也能工作；缺少QGA/驱动要返回明确失败。
5. **结果与幂等。** 只管理本场景声明的接口/路由，不修改账户、应用、AD或其它设备。已正确配置时不重复拆建网络；有界等待、取消及重试。镜像首次启动、配置完成、验证完成在真实执行事件中分别表达；网络不通过不能报告本轮部署成功。
6. **DHCP多卡兼容。** 继续支持原有DHCP路径，逐接口显式网关/DNS要求应进入端口选项；静态执行器不和DHCP争写同一张卡。未配置新字段的旧计划保持可读和可恢复。
7. **界面与文档。** 新增逐接口要求仅用于VM，Docker保留既有网络行为；VM连接迁移到Docker时提供明确清除残留要求的操作。 vNext资产/接口编辑器暴露必要的模式、网关/DNS/名称/路由要求，保留旧场景加载；解释QGA和cloud-init前提，并显示真实错误和执行阶段。准备镜像组件清单、迁移与验收手册。

具体DTO名称由契约任务先冻结，避免前后端同时猜字段。优先扩展现有Contracts/Application/Agent执行边界，不从Controller直接编排来宾命令，不新增部署队列。

## 本轮边界

不把固定IP的多副本隔离、VRF或地址池重设计并入网卡初始化任务；现有固定地址场景的地址分配约束仍需遵守。不要为了自动初始化给业务拓扑额外插入管理网卡。镜像组件需准备一次，本轮不自动改造全部旧模板。不开启攻击或题解研究，不更改原业务、教学实例或公网网关。
