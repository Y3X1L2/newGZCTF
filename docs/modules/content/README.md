# Content：镜像、附件与内容资产

Content 管理业务可复用的内容资产，重点是镜像模板、导入任务、附件文件、启动配置和运行能力元数据。题目、课程、练习和 TeamLab 都可以引用资产；比赛计分、课程学习进度和运行实例调度分别属于业务或 Runtime 模块。制作人员登记制品，教师引用到内容，管理员处理认证、删除和分发异常，外部流水线通过授权 API 上传或登记资产。

镜像先经过来源校验、导入和摘要确认，成为可查询的模板；业务绑定模板，TeamLab 发布保存模板 ID 与当时摘要。创建运行环境时先选择节点，再准备选中节点缺少的镜像。模板主状态表示源资产的就绪情况，节点分发状态表示某节点缓存的准备情况，分别维护。普通创建按选中节点准备；显式预热可提前向全部适配节点建立缓存需求。

```mermaid
flowchart LR
  A[外部制品或附件] --> B[校验及资产登记]
  B --> C[业务显式引用]
  C --> D[运行时选择节点]
  D --> E[节点缓存与执行]
  C --> F[引用检查后退役或删除]
```

附件上传按内容摘要复用文件，业务绑定与解绑负责新增和释放附件引用。删除文件前须核对全部使用方；相同 Hash 的复用文件保留各自引用。镜像删除也收集业务和运行引用，仅在有效引用全部释放后执行；课程或运行环境销毁时释放自身引用，全局主副本继续按 Content 生命周期管理。

实现以 Content 的公开目录、引用检查和运行配置 query 为模块边界，导入 worker 与 Registry/VM 制品存储完成文件侧操作。节点缓存准备目前由 Fleet 分发服务执行，Agent 负责本机下载、校验和容量保护。远程访问配置保存于模板；其他模块读取配置存在性与能力投影，密码和私钥仅用于受控的服务端连接。

代码职责与环境验收分别维护。历史回收记录限定到当次操作；自动 Blob GC、冷缓存策略、镜像冷启动的覆盖范围和后续缺口见 [当前状态](../../current-state.md)。
