# 组网模块介绍与演示讲解稿

## 一、这是什么

组网模块用于把 Docker 容器、Linux 虚拟机、Windows 虚拟机以及交换机、路由器等网络设备，组合成一套可以实际运行的独立网络环境。

它面向的不是单台靶机，而是完整场景。例如：多网段攻防环境、工控网络、企业办公网、域环境、跳板机环境，或需要多个系统相互通信的综合比赛题目。

每支队伍拿到的是一套彼此隔离的运行环境。队伍之间不能互相访问，比赛结束后环境可以统一销毁和清理。

## 二、可以解决什么问题

过去部署复杂靶场，通常需要人工创建虚拟机、配置网卡、分配地址、连接路由、检查镜像和逐台排错。组网模块把这些步骤变成统一的场景设计和自动部署流程。

管理员可以在一个画布上完成：

- 创建入口网段、业务网段、管理网段等不同区域。
- 放入 Docker、Linux VM、Windows VM、交换机和路由器。
- 为资产配置网卡、地址、资源规格和运行参数。
- 通过连线定义哪些网段可以经由哪个路由器通信。
- 校验配置后发布为可复用版本，并用于试运行或正式比赛。

这样，一个已经校验过的场景可以被不同比赛直接选用，不需要每次重新搭建。

## 三、场景如何运行

场景发布后，平台会先检查需要的镜像是否已准备到可调度节点。镜像准备完成后，平台根据节点的 CPU、内存、磁盘、Docker 和虚拟机容量，自动选择合适节点部署。

如果资产需要分布在多台服务器上，平台会自动建立它们之间的受控连接，使不同服务器上的资产仍然像处在同一套场景网络中一样通信。

运行时只创建必要的网络、虚拟机磁盘副本、容器和配置，不在启动过程中重新安装系统或修改基础镜像。这既缩短启动时间，也让每次运行的结果更稳定、更可追溯。

## 四、Docker 和虚拟机如何兼容

组网模块同时支持 Docker 和虚拟机：

- Docker 适合入口服务、Web 服务、轻量工具和快速启动的靶机。
- Linux VM 适合需要完整操作系统、真实网络服务或较低改造成本的环境。
- Windows VM 适合域环境、桌面服务、Windows 服务和需要远程桌面运维的场景。

基础组网由平台在宿主服务器侧完成，因此虚拟机不需要为了联网而修改镜像。对于已配置管理账号的镜像，管理员还可以在运行后通过 SSH、远程桌面或容器终端进入对应资产进行运维。

## 五、流量检测如何实现

平台会在场景实际使用的虚拟网卡、网桥、路由器和跨服务器连接处记录通信。

简单理解，就是流量经过网段、路由器或服务器之间的连接时，平台都能留下记录。因此可以看到：

- 哪个资产访问了哪个资产。
- 使用了什么协议和端口。
- 是否经过路由器、是否跨网段、是否跨服务器。
- 通信发生的时间、方向和经过位置。

当需要深入分析时，管理员可以针对指定网段启动抓包，保存为标准 PCAP 文件，用 Wireshark 等工具复核。常规流量记录用于持续观察，按需抓包用于排查问题和保留证据，两者不会混为一谈。

如果镜像额外配置了来宾侧观测能力，平台还可以辅助识别“某服务收到请求后，又向另一个资产发起连接”这类转发行为；未配置该能力的镜像仍可进行网络层面观测和抓包。

## 六、运维和安全控制

组网环境不是创建后就失去控制。平台支持对运行环境进行：

- 试运行：在正式比赛前验证场景是否能够部署和通信。
- 暂停与恢复：暂停后保留环境事实，恢复时不重新拉取镜像。
- 重置：恢复到该队伍当前版本的初始状态。
- 销毁：停止并清理容器、虚拟机磁盘副本、网络、路由、抓包和容量占用。
- 运维访问：管理员可访问全部资产；比赛所有者可管理自己的比赛；其他运维人员必须被单独授权；选手只能访问自己的比赛入口，不能看到其他队伍的运维信息或访问凭据。

每次发布、准备镜像、创建、暂停、恢复、销毁和运维访问都会留下状态和审计记录，便于追查问题。

## 七、现场演示建议

建议按以下顺序展示：

1. 打开场景设计页面，展示入口网段、业务网段、管理网段、交换机和核心路由器。
2. 展示 Docker 服务和 Linux/Windows VM 分别连接到不同网段，说明它们的用途和地址配置。
3. 点击校验，展示系统自动检查镜像、地址、网卡、路由和节点能力。
4. 发布版本并触发镜像准备，展示平台先完成镜像和节点准备，再允许试运行。
5. 创建试运行，展示资产状态、部署阶段和实际分配的网段地址。
6. 打开管理员运维入口，展示容器终端、SSH 或远程桌面入口。
7. 产生一次跨网段通信，打开流量页面，展示通信双方、协议、经过的网络位置和按需抓包入口。
8. 最后展示暂停、恢复或销毁，说明平台会释放运行资源并保留必要审计记录。

## 八、结束语

这个模块的目标，是把复杂网络靶场从“依赖人工部署和临时排错”，变成可设计、可校验、可复用、可观察、可运维和可清理的标准化能力。

它既可以服务于平台内部的比赛和演练，也保留了完整的接口与生命周期能力，便于后续被其他业务系统接入并统一管理。
