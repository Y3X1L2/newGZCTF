# Netlab 接入与使用

## 配置连接

1. 在底座管理界面签发已有的服务 Token，授予所选项目的环境操作权限。
2. 在 YINYU 场景管理的连接设置中填写底座 HTTP(S) 地址、项目名称和令牌。
3. 保存时通过底座身份接口检查 Token 和项目授权，成功后进入场景工作区。

项目名称填写 Token 已授权的项目。上层在此项目中按创建者及比赛队伍关联环境，资源标识由底座生成。Token 使用 ASP.NET Data Protection 加密，仅由上层服务端发送给底座。生产主站保留 Data Protection 密钥，并通过内网或 HTTPS 访问底座。

## 制作与比赛

教师在场景工作区选择模板、连接网段、设置资源并发布版本。画布、实例操作、控制台、文件、性能、流量和存储组件由底座正式前端源码迁入，在 YINYU 内构建和运行。

镜像导入及节点、存储的管理写操作使用底座原有管理员界面。上层使用普通服务 Token 选择已有模板、编排环境，并按底座实际返回的权限展示操作。

比赛管理选择场景版本，按资产名称配置目标和重建次数，然后为已通过审核的队伍部署环境。部署过程中可查看底座实际状态；开放环境后，比赛时间内的队员从比赛入口进入本队工作区。

动态 Flag 由上层按队伍和目标生成，容器通过模板参数注入；虚拟机通过来宾代理写入初始化文件。虚拟机模板启用 QEMU Guest Agent，Linux 文件位于 `/opt/gzctf/runtime/secrets/`，Windows 文件位于 `C:\ProgramData\GZCTF\Runtime\secrets\`。初始化发生在实例创建时，普通重启保留实例内的修改。

选手重建由上层检查比赛规则并调用底座。成功重建计入次数；请求中断后重试沿用相同请求标识。比赛结束或队伍退出后，后台请求销毁关联环境。手动删除比赛、队伍时同样等待底座确认销毁。

## 权限与实时状态

| 身份 | 工作范围 |
| --- | --- |
| 管理员 | 配置底座连接，管理工作区资源 |
| 教师 | 自己的场景和负责比赛的环境 |
| 选手 | 已开放、处于有效时间内的本队环境；查看、会话、访问和观测 |

浏览器请求先通过 YINYU 账号和业务权限检查，服务端使用配置的 Token 调用底座原有 API。教师资源归属取自环境创建者及负责的比赛，选手访问范围取自当前队伍绑定。用户、角色和比赛权限统一由 YINYU 管理。

浏览器沿用同源 `/api/teamlab/netlab/` 入口。普通业务 JSON 请求有 30 秒超时；上传、SSE 和 WebSocket 按流持续转发。长连接每 30 秒重查账号与业务访问范围，账号停用、登录凭据或权限变化会终止原连接。状态事件来自底座 SSE，页面按事件更新。

## 更新与上线

底座返回当前资源、状态和权限，上层据此更新页面。组件源码随 YINYU 发布；增加页面功能时同步对应组件和公开契约。底座仅增加通用虚拟机初始化文件能力，其余 API、Token 和授权机制保持已有契约。

本次完成代码和功能接入。现有数据迁移安排在上线窗口：先备份数据库及配置，核对旧场景、镜像、运行实例与活动队列；将需要保留的数据迁入底座并绑定；完成旧执行资源清理和任务结束后，切换新上层。历史实体保留原数据与引用，供迁移核对。上线顺序和验收见 [发布手册](../../operations/vnext-maintenance-window-rollout.md) 与 [本次记录](../../records/2026-11-10-netlab-integration.md)。
