## 3. 量化退出门槛

Phase 2 退出必须同时满足：

1. `pnpm validate:locales`、`pnpm check`、`pnpm build` 全部通过。
2. 架构扫描不允许新增页面级全局视觉选择器，不允许页面直接导入生成 API 文件。
3. 三个高风险页面至少拆出明确的 controller、业务面板和展示组件边界。
4. API 生成文件不再位于业务源码根目录，生成命令输出到固定隔离目录。
5. 前端可独立生成带版本清单的制品；后端可在不安装 Node.js 的情况下使用该制品发布。
6. 路由 chunk 单文件 gzip 预算：普通页面不超过 350 KiB，重型拓扑/大屏页面不超过 900 KiB；超限必须在清单中说明。
7. 首屏共享 JS 不引入 Three.js、ECharts、PDF、Shiki 或 React Flow；这些依赖只能进入按需 chunk。
8. 360 像素宽度下核心查看和提交操作可用；数据表允许容器内横向滚动，但页面本身不得产生无意义横向滚动。
9. `prefers-reduced-motion: reduce` 下关闭持续背景动画、视差和高频闪烁。
10. 部署后的 `index.html`、静态资源和后端版本可以从发布清单追溯并独立回滚。

## 4. 实施顺序

```text
契约与基线
  -> API 与请求层
  -> Token / Theme
  -> 公共组件
  -> 高风险页面拆分
  -> 性能与响应式
  -> 独立制品
  -> 部署验收
```

不得从首页重新设计直接开始。新视觉必须建立在 Token、Theme 和公共组件完成之后，否则会继续扩大现有覆盖链。

## 5. 非目标

- 本阶段不修改比赛、培训、AWDP、TeamLab 的后端业务语义。
- 本阶段不恢复 Phase 0 已删除的旧培训或 Scenario 模型。
- 本阶段不把所有历史页面一次性重写；历史页面通过兼容层逐步迁移。
- 本阶段不完成 Phase 11 首页产品定位和练习模块，只提供其可复用前端底座。
