# TeamLab 组网场景功能说明

## 1. 功能定位

TeamLab 用于把容器、Linux 虚拟机、Windows 虚拟机和网络设备组织成可重复使用的网络安全演练场景。管理员完成一次设计、校验和发布后，可以把同一套正式版本用于比赛、培训或独立试运行；每个队伍获得相互隔离的一套运行环境。

组网模块负责网络连接、资源安排、镜像准备、环境创建、访问入口、运行观测和回收。镜像内的业务服务，例如 AD 域、工控服务、漏洞程序或 Web 应用，由镜像本身、场景预制结果或已声明的服务注入配置提供。

## 2. 场景设计

管理员在“组网场景”中使用画布完成设计，支持以下资产：

- 交换机：承载一个隔离网段，连接该网段中的资产。
- 路由器：连接多个网段，并按设计允许或限制网段间通信。
- Docker 容器：适合入口服务、轻量应用和中间件。
- Linux 虚拟机：适合需要完整 Linux 系统的服务或靶机。
- Windows 虚拟机：适合 Windows 服务、域环境和桌面系统靶机。

场景可以包含多个网段。每个资产可配置网卡所属网段、固定主机偏移、网卡顺序和主网卡；主网卡承载默认网关，其他网卡只加入其所属网段的直连通信。未被路由器连接的网段默认隔离。

画布提供拖动、缩放、适配视图、专注模式、复制、撤销、重做和“一键自动排版”。自动排版只整理显示位置，不改变资产、网络或路由关系。

## 3. 资产配置与高级配置

每个资产可设置镜像模板、CPU、内存和存储需求。系统按照模板类型识别 Docker 或虚拟机能力，不会因节点缺少 KVM 而阻断 Docker 资产。

“高级配置”用于填写运行期参数：

- 运行参数：是否启用资产路由、是否暴露服务端口。
- 环境变量：普通配置值，例如 `DEMO_MODE=showcase`。敏感值不在这里保存，应通过运行期 secret 注入。
- 启动命令：留空时使用镜像默认命令；填写后按该命令启动资产。
- 健康检查：只在场景确实需要确认某个 TCP 或 HTTP 服务已可用时启用。未配置健康检查的资产以成功启动和完成初始化为准，不会被默认 ICMP 探测误判失败。
- 服务注入：只可引用已经声明并签名的 Bootstrap Profile，用于轻量运行期初始化。
- 流量观测：可按资产设置禁用、可选或必需的端点观测等级。
- 发布时预制：适用于 AD 域、工控等需要多次启动或长时间初始化的场景。预制成功后保存为可复用制品，正式运行时不重复安装服务。

## 4. 校验与发布

当前设计是草稿，草稿修改不会影响已发布版本或正在运行的环境。

点击“校验”后，平台会用中文提示网络、地址、连接、镜像、资产能力、启动依赖和资源配置问题。校验通过后才能发布。

发布会生成不可修改的正式版本：

1. 正式版本保存当时的完整场景配置。
2. 后续修改仍保留在草稿中，下一次校验通过后发布为新版本。
3. 比赛或培训应绑定正式版本，而不是直接使用草稿。
4. 同一正式版本可以重复用于多次试运行和多个业务场景。

“当前设计”和“发布版本”明确分开：前者用于编辑，后者用于稳定运行。已通过校验的发布版本不需要因为草稿后续变化而重新校验。

## 5. 镜像准备与节点分发

内部镜像仓库保存 Docker 镜像和虚拟机镜像的主副本。发布版本页会显示每个模板的可用节点、已就绪、分发中和失败数量。

镜像准备遵循以下规则：

- Docker 模板只分发到支持 Docker 的节点。
- 虚拟机模板只分发到支持 KVM 的节点。
- 同一模板已在目标节点且校验通过时直接复用，不重复下载。
- 试运行或正式创建前会再次确认镜像状态；缺失时单独进入“镜像准备”阶段，而不是把下载与设备创建混在一起。
- 失败信息会包含模板、目标节点、内部仓库地址和具体原因。
- 运行环境销毁时只释放本环境的镜像引用；仍被其他比赛、课程或运行实例使用的节点缓存不会被删除。

## 6. 试运行与正式运行

试运行用于在不绑定正式比赛的情况下验证已发布版本。创建试运行时，平台依次完成：

1. 检查发布版本、节点能力和资源余量。
2. 预留容器、虚拟机、CPU 和内存资源，避免并发创建超出节点容量。
3. 按网段把场景安排到一个或多个计算节点。
4. 建立网段、路由、隔离规则和跨节点加密连接。
5. 准备缺失镜像，创建容器和虚拟机。
6. 等待系统初始化、服务注入和已配置的健康检查完成。
7. 汇总所有节点的真实结果，进入“运行中”。

平台优先把同一队伍的环境放在同一计算节点。单个节点容量不足时，平台按网段拆分到多个节点，并自动保持跨节点网络连通。每次创建或重置都会生成新的运行代次，旧任务不能覆盖新环境。

运行详情页展示部署阶段、资产数量、节点分片、网段、资产地址、事件与日志。试运行支持重置和销毁；重置先清理当前代，再基于同一发布版本创建下一代。

## 7. 比赛、培训与选手访问

正式比赛可绑定发布版本，并在赛前准备阶段提前分发镜像。比赛开始后，平台按队伍创建隔离运行环境；不同队伍的地址、网络、运行资源和动态数据相互独立。

选手只会获得场景定义的入口网段访问权限，不会获得计算节点管理地址、临时转发端口或其他队伍环境的访问权限。访问配置与环境生命周期绑定，环境重置或销毁后自动失效。

## 8. 管理员运维访问

平台支持对运行资产进行受控运维访问：

- Docker 容器使用网页终端。
- Linux 虚拟机使用网页 SSH。
- Windows 虚拟机使用网页 RDP。

超级管理员和管理员可访问全部资产；比赛所有者可访问自己比赛下的资产；其他人员必须被单独授予查看或进入运维资产的权限。浏览器不会获得节点地址、转发端口、密码或私钥。

每次运维访问均记录操作人、目标资产、访问原因、开始和结束时间、终止原因及相关审计文件。环境销毁、重置、权限撤销或会话超时后，临时访问通道会被关闭。

## 9. 流量观测与抓包

运行环境可记录资产间通信的源地址、目标地址、端口、协议、方向、流量大小、时间和经过的网络位置。管理端可查看通信流、通信路径和按需抓包结果。

对于 A 到 B、B 到 C、C 回到 B、B 回到 A 的链路，平台按实际观测到的分段通信记录，不把推测关系伪装成单包级结论。抓包可限定范围、时长、文件大小和保存期限，下载行为也会进入审计记录。

## 10. 销毁与资源回收

销毁由平台统一发起，节点只清理能通过运行环境编号和代次确认归属的资源。清理范围包括容器、虚拟机、临时磁盘、网段、路由、隔离规则、跨节点连接、访问授权、抓包任务、资源预留和镜像引用。

只有所有节点反馈清理完成后，运行环境才显示“已销毁”。如果清理中断，平台保留待清理状态和错误原因，不会把未完成的清理误标为成功。

## 11. 权限与安全边界

- 场景编辑、发布、试运行、比赛绑定和运行销毁均经过平台权限检查。
- 平台不向选手开放节点管理能力，也不允许通过修改运行实例或资产编号跨环境访问。
- 镜像、运行状态、节点分发状态和部署队列分别记录，避免把“模板可用”误认为“节点已准备”。
- 密码、私钥、动态 Flag、WireGuard 私钥和完整用户数据不会写入普通日志、发布版本或公开 API 响应。
- 容器、普通虚拟机和组网环境使用统一资源预留与部署队列，避免相互挤占未统计的容量。

## 12. 对外 API

对外调用使用统一入口：

```text
/api/open/v1/teamlab
```

主要能力包括：读取平台能力、创建和更新场景、校验场景、发布版本、生成部署预览、创建运行实例、查询运行状态、重置、销毁、查询事件、管理选手访问授权、查询流量和管理抓包。

长时间操作返回操作编号，可通过：

```text
GET /api/open/v1/operations/{operationId}
```

查询阶段、进度和结果。完整字段、权限范围和请求示例见：

- `docs/commercialization/open-api-v1-guide.md`
- `docs/commercialization/teamlab-api-foundation-contract.md`
- 部署后的中文 API 页面：`/api-docs/`
