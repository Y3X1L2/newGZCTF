## 1. 阶段定位

本阶段在已完成的 vNext 公共壳、赛事、培训和共享交互基线上，建立新的管理域前端。

目标不是一次性复刻所有旧后台页面，而是先完成 API 已就绪、复用收益最高的运维纵向切片：

1. 管理壳与真实状态首页。
2. 环境模板。
3. 节点列表与节点详情。
4. 部署队列。
5. 运行实例。
6. 系统日志。

完成后，赛事管理、用户管理、理论题库和 TeamLab 管理页面可以复用同一套列表、筛选、分页、状态、详情和危险操作基础。

## 3. 设计原则

- 管理页面是安静、紧凑、适合重复操作的工作界面，不使用营销式 Hero、装饰性大卡片或持续背景动画。
- 管理壳使用分组侧栏；上下文栏只显示页面身份、环境状态和最多三个主要操作。
- 表格列宽稳定，筛选和分页写入 URL；刷新、前进和后退后恢复状态。
- 行详情统一使用右侧抽屉，抽屉头尾固定、中部独立滚动。
- 页面级不产生横向滚动。窄屏下保留关键列，其余信息进入详情抽屉。
- 状态不能只依赖颜色；图标、文字和数值必须同时存在。
- 所有危险操作使用 `VNextConfirmDialog`，显示对象、影响范围和不可恢复后果。
- 页面组件不直接调用原始 `fetch`，统一通过领域 Adapter 和 Hook。
- 只对 Processing、Queued、Running 等活跃对象轮询；终态停止轮询。

## 4. 路由与页面结构

### 4.1 管理壳 `/admin/*`

左侧导航分组：

- 概览：运行概览
- 资源：环境模板、运行实例
- 运维：节点、部署队列、系统日志
- 后续占位：赛事、培训、用户、系统

未实现入口显示明确状态，但不跳回旧页面。

管理壳职责：

- 管理权限校验。
- 当前分组和页面标题。
- 桌面侧栏、移动端导航抽屉。
- 页面操作插槽。
- 页面级加载、无权限和错误边界。

### 4.2 管理首页 `/admin/dashboard`

首版不伪造聚合数据，由 Adapter 并行读取现有接口：

- 节点在线与容量。
- 活跃部署队列和失败任务。
- 运行实例。
- 最近错误日志。
- 镜像导入异常。

页面结构：

- 顶部 4-6 个关键指标。
- 中部节点容量和部署队列摘要。
- 底部异常列表和最近错误。

后端提供 `GET /api/admin/dashboard/overview` 后，仅替换 Adapter，不修改页面组件。

### 4.3 环境模板 `/admin/images`

顶部：Registry 状态、模板总数、处理中、异常、总大小。

工具栏：

- 搜索。
- 类型、OS、状态筛选。
- 注册 Docker。
- 上传 Docker Archive。
- 上传 VM/通用包。
- 导入服务器本地文件。

表格列：名称、类型、OS、Registry/Hash、真实大小、状态、进度、引用数、创建时间、操作。

交互：

- Processing 行低频刷新，进入 Ready/Error 后停止。
- Error 行打开详情抽屉，显示阶段、错误和可执行修复。
- 删除前读取引用关系；存在引用时默认禁止删除。
- 上传完成后等待服务端处理状态，不把上传请求成功当成模板可用。

### 4.4 节点列表 `/admin/nodes`

顶部：在线节点、Docker 容量、VM 容量、告警、新增节点。

表格列：名称、地址、角色、在线、Docker、KVM、镜像存储、TeamLab、容量、最后心跳、操作。

新增节点使用五步向导：

1. 连接信息。
2. 环境检测。
3. 安装与配置预览。
4. Bootstrap 确认。
5. 注册与心跳确认。

错误必须区分连接失败、权限不足、软件源不可用、Docker/KVM 缺失和 Agent 注册失败。

### 4.5 节点详情 `/admin/nodes/:nodeId`

顶部显示节点身份、在线状态、地址和主要操作。

Tab：

- 资源
- 容量
- 网络
- Agent
- TeamLab
- 事件

资源 Tab 统一显示容器、VM、培训、比赛和 TeamLab 资源；销毁操作需要确认所有者和业务影响。

网络检测只在用户主动点击时执行，不做无限自动探测。

### 4.6 部署队列 `/admin/queue`

筛选：状态、资源类型、节点、时间。

表格列：请求、资源、目标节点、状态、队列位置、槽位、耗时、错误、操作。

行为：

- 存在活跃任务时每 10 秒刷新。
- 保持当前分页和筛选。
- 等待或已分配任务按服务端能力取消。
- 长错误放入详情抽屉，不撑宽表格。

### 4.7 运行实例 `/admin/instances`

筛选：领域、类型、节点、状态、所有者。

列表统一展示 Docker、VM、比赛、培训和测试实例。

字段：所有者、业务上下文、题目、节点、入口、创建时间、到期时间、状态、操作。

销毁后等待服务端确认或任务状态，不在前端直接移除并假定成功。

### 4.8 系统日志 `/admin/logs`

筛选：时间、级别、模块、用户、节点和关键词。

表格：时间、级别、来源、摘要、关联对象。

交互：

- SignalR 新日志进入缓冲区，用户主动合并，避免列表跳动。
- 结构化详情抽屉展示属性和关联对象。
- 长堆栈独立滚动并默认折叠。
- 服务端负责 Flag、密码、Registry 凭据和 SSO Token 脱敏。

## 5. 共享组件与代码边界

新增目录建议：

```text
src/vnext/features/admin/
  shell/
  dashboard/
  images/
  nodes/
  queue/
  instances/
  logs/
  shared/
```

共享组件：

- `AdminShell`
- `AdminPageHeader`
- `FilterToolbar`
- `DataTable`
- `DataTableColumnVisibility`
- `PaginationBar`
- `StatusBadge`
- `ResourceMeter`
- `DetailDrawer`
- `EmptyTableState`
- `ActiveRefreshIndicator`

约束：

- `DataTable` 只负责表格结构、列和交互，不接收领域 API。
- 状态映射保留在各领域模块，不创建全平台万能状态函数。
- 上传、节点 Bootstrap、任务取消和实例销毁由各自 Adapter 管理。
- 管理页面不得复用旧管理页面后通过 CSS 隐藏内容。

## 6. API Adapter 规划

| 模块 | 当前 API 命名空间 | Adapter |
| --- | --- | --- |
| 首页 | `nodes`、`deploymentQueue`、`admin`、`imageTemplate` | `adminDashboardApi` |
| 镜像 | `imageTemplate` | `imageTemplateAdminApi` |
| 节点 | `nodes` | `nodeAdminApi` |
| 队列 | `deploymentQueue` | `deploymentQueueAdminApi` |
| 实例 | `admin.useAdminInstances` 等 | `instanceAdminApi` |
| 日志 | `admin.useAdminLogs`、`/hub/admin` | `adminLogApi` |

Adapter 负责：

- 生成稳定查询键。
- 将分页、筛选和排序参数转换为 API 参数。
- 统一错误模型。
- 定义活跃状态轮询规则。
- 在变更成功后精确刷新相关缓存。
- 隔离生成 API 的命名变化。

- 页面缩放：100%、125%、200%。

- 表格无页面级横向滚动；窄屏信息可进入详情抽屉。
- 所有上传和任务操作验证真实终态，不以 HTTP 200 作为完成标准。

## 9. 风险与前置决策

1. 管理首页聚合接口尚未提供。首版使用 Adapter 并行读取，后续切换聚合接口。
2. 节点 Bootstrap 涉及 SSH、sudo、Docker/KVM 和软件源，前端必须展示阶段性错误，不能只显示一个失败字符串。
3. 镜像引用关系如果后端缺少查询接口，删除动作应先禁用并标记后端需求，不能允许盲删。
4. 日志敏感信息必须由服务端脱敏；前端仅做显示，不承担安全边界。
5. 运行实例和队列存在异步终态，所有变更界面必须保留 Pending 状态并允许恢复。

## 10. 完成后的预期结果

- 管理员可以在统一设计语言下完成资源和运维日常工作。
- 镜像、节点、队列、实例和日志页面不再使用各自独立的缩放和布局。
- 管理列表、筛选、分页、详情抽屉和危险操作形成稳定复用基础。
- 后续赛事、理论题库、用户和 TeamLab 管理开发不再重新设计管理壳和表格体系。
- vNext 继续保持与旧视觉代码隔离，生产包和质量门禁不回退。
